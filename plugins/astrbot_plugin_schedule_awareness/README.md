# 大肥鱼的日程觉醒

让大肥鱼在聊天时知道“程序里真正安排了哪些定时任务”，能说清任务内容和执行时间。

## 插件是什么

这是大肥鱼项目维护的日程感知插件，插件名为 `astrbot_plugin_schedule_awareness`。
它在每次模型聊天前读取当前会话关联的有效定时任务，把清单提供给模型，帮助回答日程问题。

创建、修改、删除任务以及到点执行，由 AstrBot 的定时任务能力负责。
本插件负责提供日程背景，启用后不会自行增加新的安排，也没有单独的命令或定时器。

## 能做什么

- **回答真实日程**：让它知道程序里已经创建且启用的任务，减少“明明有安排却说没有”的情况。
- **说明什么时候执行**：显示一次性任务、每天的任务及下次运行时间；复杂周期可能显示为 cron 表达式。
- **按会话区分**：私聊读取该私聊关联的任务，群聊读取该群关联的任务；同一个群属于同一会话。
- **跟随修改刷新**：每轮重新读取，修改或删除任务后，下一轮聊天会使用最新的有效清单。
- **补充简短背景**：提供任务名称和简短说明；每轮最多展示十条，更多任务请在后台查看完整列表。

## 怎么用

### 1. 启用插件

在 [AstrBot 管理后台](http://127.0.0.1:6185)的插件管理中启用“大肥鱼的日程觉醒”。
插件随本项目安装，无需额外填写参数，也不需要为它单独配置模型或密钥。
它本身只读取任务，不增加额外的模型调用；正常聊天仍使用当前会话的模型。

如果还需要通过聊天创建或修改任务，当前模型和人格应允许使用 AstrBot 的 `future_task` 工具， 并且
AstrBot 定时任务服务可用。插件启用与任务成功创建是两件需要分别确认的事。

### 2. 体验一次“创建后还能问出来”的提醒

在 **同一个 QQ 会话**中依次操作。以下内容通过正常聊天发送，不需要加命令前缀。

**第一步：创建一个容易核对的任务。**

> 请创建一个名为“体验日程提醒”的一次性任务，十分钟后提醒我休息一下。

确认 AstrBot 的定时任务工具实际返回成功，并给出了任务标识或安排时间。
可以再到后台的定时任务列表核对；仅回复“好的，我会提醒你”还不能算创建成功。

**第二步：问它现有日程。**

> 你现在有哪些已经安排好的任务？“体验日程提醒”什么时候执行？

它应能说出刚才任务的内容和时间，并与后台记录一致。 时间使用任务配置的时区，未指定时通常按上海时区显示。

**第三步：修改后再问。**

> 把“体验日程提醒”改成二十分钟后执行，其他内容不变。

确认修改工具返回成功，再问“这个提醒现在什么时候执行”。 回答应跟随更新后的安排，无需重载本插件。

**第四步：核对实际提醒或取消。**

如果要验证到点投递，保持 AstrBot、QQ 连接和任务启用，等到点后确认是否实际收到提醒。 如果只体验日程查询，可在到点前发送：

> 请取消“体验日程提醒”，再查询程序里当前仍有效的任务，确认它已经取消。

取消也需要任务工具确认。普通对话中的旧提及不代表任务仍然有效。

### 3. 平时可以这样问

| 想了解什么     | 可以发送                                             |
|----------------|------------------------------------------------------|
| 当前安排       | “你现在有哪些已经建立的定时任务？”                   |
| 某项提醒的时间 | “刚才的休息提醒什么时候执行？”                       |
| 调整安排       | “把这个提醒改到明天上午九点，确认修改成功后告诉我。” |
| 删除安排       | “取消刚才那个提醒，并查询确认。”                     |

查询日程会使用本插件提供的背景；新增、修改和取消仍需实际调用 AstrBot 的任务工具。 存在多个相似任务时，应明确名称或任务
ID。

### 4. 常见问题

| 现象                         | 怎么处理                                                                           |
|------------------------------|------------------------------------------------------------------------------------|
| 说“记住了”却查不到任务       | 先到后台核对是否真正创建，以及是否启用；聊天承诺或长期记忆不等于定时任务           |
| 私聊创建的提醒在群里问不出来 | 在创建任务的原会话查询；不同私聊和群聊的任务按会话区分                             |
| 后台有任务，聊天里仍看不到   | 检查任务是否启用、是否关联当前会话；超过十条时后台列表更完整                       |
| 能说出任务，到点却没收到     | 检查任务执行记录、AstrBot 与 QQ 在线状态及发送结果；看见日程不代表投递已经成功     |
| 改了时间，回答仍引用旧时间   | 核对修改工具是否成功，再明确要求查询当前有效任务；必要时检查插件是否加载及读取日志 |
| 无法创建、修改或取消         | 检查模型是否能使用 `future_task`、操作权限及定时任务服务；本插件不单独执行这些操作 |
| 模型接口报错，无法回答问题   | 先恢复当前聊天模型；日程清单随模型请求提供，最终回答仍需要模型正常返回             |

日程被正确说出、任务按时执行、QQ 实际收到提醒是三个不同的核验步骤。 一次性任务完成后可能被删除；之后的聊天不应把它继续当作仍待执行的安排。
