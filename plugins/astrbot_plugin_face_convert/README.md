# QQ 表情文字转换

让大肥鱼的 QQ 回复可以带上真正的 QQ 表情，并配合项目配置处理语音、视频和角色配图。

## 插件是什么

这是大肥鱼项目维护的聊天增强插件，插件名为 `astrbot_plugin_face_convert`，用于 NapCat / OneBot QQ 通道。
名字保留了最初的“表情转换”功能，目前也承接项目中的语音回复、视频理解和自拍等适配。 它随本项目安装和更新，部分能力需要项目的
AstrBot 补丁及其他插件共同工作。

## 能做什么

| 功能               | 实际用途                                                                 |
|--------------------|--------------------------------------------------------------------------|
| 发送真正的 QQ 表情 | 把回复里的 `[流泪]`、`[doge]` 等已收录名称转换成 QQ 表情消息             |
| 理解收到的表情     | 把收到的 QQ 表情名称交给聊天模型，纯表情消息也能进入对话                 |
| 语音交流           | 转写收到的语音；允许时把适合出声的回复合成为语音，文字与语音尽量不重复   |
| 视频理解           | 分段转写视频声音、间隔抽取画面，将实际识别到的内容交给聊天模型           |
| 图片对话           | 配合项目视觉功能，根据当前图片和你的问题回答，区分图片内容与发图人的状态 |
| 自拍与动作配图     | 有可用生图工具时，响应自拍、摆姿势等明确请求，并接着聊天                 |
| 回复整理           | 清理部分内部格式和草稿残留，规范标点，减少同一意思反复表达               |

## 怎么用

### 1. 启用和准备

在 [AstrBot 管理后台](http://127.0.0.1:6185)的插件管理中启用“QQ表情文字转换”。
基础表情转换无需填写额外参数；模型和媒体服务通过项目根目录的 `配置向导.cmd` 配置。

| 想用的能力         | 需要准备什么                                                                    |
|--------------------|---------------------------------------------------------------------------------|
| 表情互动和普通聊天 | QQ 通道正常、聊天模型可用                                                       |
| 接收语音和理解视频 | 本项目使用的百炼语音识别、视觉服务及对应 Key；视频还需项目安装的 FFmpeg         |
| 发出普通聊天语音   | AstrBot 已启用 TTS、当前会话有可用语音模型；配置该节点的 API Key 后默认允许输出 |
| 图片理解           | 项目视觉模型或图片描述服务可用                                                  |
| 自拍、动作图片     | 万象画卷的生图服务、参考图及 `generate_selfie` 工具可用，并具有相应权限         |

修改配置后按项目流程部署更新、重载相关插件。语音识别、合成、视觉和生图可能产生对应服务的 API 消耗。

### 2. 直接体验

在能正常聊天的 QQ 会话中，按需选一种尝试；群聊沿用原有的唤醒和权限设置。

**表情：**发送“回复我一个 doge 表情”。如果模型回复中使用 `[doge]`，你应收到真正的 QQ 表情。 也可以直接发一个
QQ 表情，观察它是否能理解并接话。

**图片接话与转场：**分享图片或表情包时，默认根据这次表达接话；图片也可以开启新话题。
前文用于理解相关语境和指代，不重复摘录最后一句文字来固定图片主题。明确要求读字、解释或排错时仍按问题处理。
闲聊允许自然转场的规则在人格中维护，更新补丁后还需执行 `python tools/launch.py sync-persona --apply`
同步人格正文。例如刚聊过午饭，随后分享恋人招租表情包，可以直接聊新图里的玩笑；
再问“回到刚才午饭那个事”时，则结合之前的信息接回去。“你呢？”这类省略表达仍参考相关前文。

**语音：**配置当前语音节点的 API Key 后，首次使用默认允许语音，可以直接发送“用语音说一句：晚上好，今天辛苦了”，
检查实际收到的语音是否能播放。尚未配置 Key 时默认关闭；使用免 Key 的语音节点时，可以用 `/语音开`
显式允许输出。
开启后仍以文字聊天为主，不会把每句话都朗读一遍。控制命令：

明确想听时可以自然表达，例如“我想听听你 ‘生气’ 时的声音”“模仿一句英雄的台词声音看看”或“给这段文字配音”。
角色声音、台词演绎和朗读会使用当前可用音色出声，不代表复刻了指定角色的原声音色。聊天模型在同一轮回复中选择语音，程序对明确出声请求兜底转换，
不要求固定句式；明确请求可绕过普通闲聊冷却，关闭语音或不方便听的要求仍优先。合成失败时保留文字回复。

| 命令        | 用途                                         |
|-------------|----------------------------------------------|
| `/语音开`   | 显式开启当前会话的普通聊天语音输出           |
| `/语音状态` | 查看当前会话的普通聊天语音开关               |
| `/语音关`   | 关闭当前会话的普通聊天语音输出，保留文字交流 |

显式开关会按会话持久保存，重启或更换 Key 后仍优先使用该状态；没有显式设置时，默认状态随当前启用的语音节点及其
Key 变化。
这些命令控制当前会话的普通聊天语音；主动消息有独立语音设置，接收语音后的转写也单独工作。

**视频：**先发一段十至二十秒、声音清楚的 QQ 视频，再问“这段视频主要讲了什么”。
检查回答是否对应画面和声音；抽帧可能遗漏瞬间动作，不能把识别摘要当作逐帧观看结果。

**自拍或动作配图：**准备好生图服务后，可发送“发张自拍给我”，或“给我摆个姿势”。
实际收到图片才算成功。未配置视频工具时，明确的跳舞、转圈、摆姿势请求可以通过一张静态动作图呈现。
也可以直接说“我要看你跳舞的样子”“跳舞的图片”或“让我看看你转圈的样子”。
静态图不代表动画或视频；只要求视频时不会自动替换成图片，讨论别人跳舞或取消发图也不会触发动作配图。

### 3. 默认限制与高级参数

| 项目         | 默认行为                                                       |
|--------------|----------------------------------------------------------------|
| QQ 表情      | 一条回复最多转换两个；当前会话最近重复使用的表情可能被冷却抑制 |
| 表情冷却记录 | 十分钟内有效，按会话区分                                       |
| 视频文件大小 | 最大 80 MiB                                                    |
| 视频范围     | 最多处理前五分钟，均匀抽取最多十六帧                           |
| 视频声音     | 每六十秒一段，分别转写                                         |
| 视频等待     | 最多等十秒获得处理空位，开始处理后最多五分钟。超时或部分失败时返回已取得的结果 |
| 并发媒体     | 同时处理一条媒体，视频内部最多两个处理任务                     |

无需调优时保持默认即可。高级参数从 **运行目录**中的
`astrbot/data/plugins/astrbot_plugin_face_convert/config.json` 读取，没有此文件时使用内置默认值。
已有配置中的值优先于默认值。升级后若仍受旧的文件大小或超时限制，可在原文件里更新对应字段，
保存后重载插件。部署入口见[脚本使用说明](../../scripts/README.md)。

常用字段为 `face_cooldown_minutes`、`max_media_mb`、`video_max_duration_s`、
`video_max_frames` 和 `video_timeout_s`。默认五分钟视频最多发起四次画面识别和五次音频转写，
提高帧数会增加识别消耗和等待时间。

### 4. 常见问题

| 现象                              | 怎么处理                                                                     |
|-----------------------------------|------------------------------------------------------------------------------|
| 开了语音却仍回复文字              | 先检查 TTS 服务及会话开关，再明确提出语音请求；普通闲聊默认优先文字          |
| 没听懂我发的语音                  | 检查百炼语音识别服务、密钥与接口区域；发送更短、更清楚的语音重试             |
| 同一个表情没有连续出现            | 可能触发表情冷却；未收录的名称也不会转换成对应 QQ 表情                       |
| 视频只理解了一部分                | 留意回复中的识别范围或失败提示；长于五分钟的后续部分不处理，可剪短后分开发送 |
| 自拍或动作请求只返回文字          | 检查万象画卷、可用的生图工具、接口额度与使用权限，实际图片回执才代表已发图   |
| 关闭语音后还有主动消息出声        | 普通聊天和主动消息的语音设置独立，需再检查主动聊天插件的配置                 |
| 出现 `402 / Insufficient Balance` | 检查报错所对应的模型服务余额，确认该服务恢复后再试                           |
