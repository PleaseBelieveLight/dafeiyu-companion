# 大肥鱼自主生活

让大肥鱼有一本可以接着写的“目标本”和“经历本”：记下准备做什么、研究到了哪里， 下次继续同一个目标，并在聊天时说清自己的进展。

## 插件是什么

这是大肥鱼项目自行维护的 AstrBot 插件，插件名为 `astrbot_plugin_life_continuity`。 目前面向 **配置的主人
QQ 私聊**，主要活动是研究文字资料、整理笔记，可选接入当前会话的联网搜索。研究复用当前会话的模型，
使用简短的资料研究协议与角色身份，会消耗模型 API 额度；对外聊天继续使用所选人格。

每次推进一个有限步骤，可由主人手动启动，或显式开启每日自动推进。目标和进度保存在本地，重载或重启后仍可查询；
异常中断的目标先暂停，核对后再继续。联网模式保存搜索返回的摘要与链接，不代表阅读全文，也不操作游戏。

## 能做什么

- **管理目标**：记录研究主题、理由、结束条件和下一步，最多保留三个未结束目标，搁置也占名额。
- **研究并留笔记**：根据资料记录发现、待核实问题、来源和下一步；完成一轮不代表整个目标完成。
- **聊天接上进度**：可以问“最近在研究什么”“研究到哪了”，让它根据已有记录回答。
- **如实说明执行状态**：聊天读取最后运行时间、暂停原因、检索记录和真实执行器状态；历史承诺不作为执行依据。
- **可选每日推进**：围绕已有目标检索新资料、保存来源、写笔记；重复摘要不算新进展，不生成新笔记或分享。
- **选择和调整方向**：从有资料的候选中选择目标，记录理由；分别保存自己的研究倾向和主人明确表达的偏好。
- **由主人控制**：暂停、继续、调整、纠错、搁置、放弃或确认完成，保留已有发现和修改记录。
- **可选记忆与分享**：显式保存经历到 LivingMemory，或在研究后主动分享摘录；两者都有独立开关。

## 怎么用

### 1. 打开配置

本项目的安装和部署更新会复制此插件。在运行机器打开
[AstrBot 管理后台](http://127.0.0.1:6185)，进入插件管理，找到“大肥鱼自主生活”，编辑配置。

| 配置项             | 含义                                 | 手动体验时怎么设置                                                           |
|--------------------|--------------------------------------|------------------------------------------------------------------------------|
| `enabled`          | 总开关                               | 开启                                                                         |
| `owner_scope`      | 主人完整私聊会话标识                 | 填写实际会话标识，格式为 `平台实例ID:FriendMessage:主人QQ号`，不能只填 QQ 号 |
| `activity_enabled` | 允许研究和目标选择                   | 开启                                                                         |
| `web_search_enabled` | 每轮调用当前会话的联网搜索一次     | 需要自动找资料时开启，先在 AstrBot 配好联网搜索                              |
| `auto_enabled`     | 每天最多自动推进一轮已有目标         | 手动体验时关闭，需要每日推进时开启                                         |
| `auto_hour`        | 上海时间每天从此小时开始等待空闲     | 默认 10，范围 0–23                                                          |
| `search_timeout_seconds` | 单次检索超时                   | 默认 15，范围 1–30，同时受整轮时间限制                                     |
| `trial_mode`       | 严格试运行，每个上海日期最多开始一轮 | 手动体验可关闭；正式限频观察时开启                                           |
| `memory_enabled`   | 允许显式调用长期记忆                 | 初次体验可关闭；需要时再开启，并核验 LivingMemory 的会话隔离                 |
| `share_enabled`    | 研究后主动分享进展                   | 初次体验可关闭，通过聊天查看结果                                             |
| `followups_enabled` | 记挂、跟进和跨天角色状态            | 体验私聊连续性时开启                                                        |

公开默认配置的开关均关闭，主人会话留空。 **保存配置后重载插件。**
保留项目自带的主动聊天插件及发送适配，它们用于核验免打扰和共享消息额度；关闭研究分享时也需要。
研究前先确认普通模型聊天可用，并避开免打扰时段；普通聊天后默认冷却五分钟。

关闭 `trial_mode` 后，活动时间、模型调用次数、消息额度和免打扰限制仍然生效；自动推进只由 `auto_enabled` 开启。
默认每日后台活动累计十分钟、模型调用二十次，约定跟进、主动分享与既有主动聊天合计每天一份。这些是本插件的统计范围，不是全部
API 消耗的账单。

### 跨天记挂与角色状态

启用 `followups_enabled` 后，在配置的主人私聊中直接发送文字。约定和状态保存在本地，重启后可以继续。

| 想做什么 | 发送示例 |
|---|---|
| 记住一件事，下次聊到时接上 | `记挂 面试结果` 或 `下次继续聊面试结果` |
| 约一次主动跟进 | `明天9点问我 面试结果` 或 `明天方便时问我面试结果` |
| 给尚未尝试发送的跟进改期 | `改期记挂 面试结果 \| 明天11点` |
| 查看约定 | `记挂事项` 或问“昨天约好的事是什么” |
| 结束或取消 | `完成记挂 面试结果` 或 `取消记挂 面试结果` |
| 暂停或恢复主动联系 | `先别主动找我` 或 `可以主动找我了` |

“明天方便时”从上海时间次日 09:00 起等待合适时机，普通跟进遵守免打扰、聊天冷却和共享额度。
当天待跟进的约定优先于研究分享。超过约定时间 24 小时仍未发送的事项留到下次聊到它时接上。
已发送或投递待核实的跟进不会自动重试。需要准点执行的请求使用“明天9点提醒我交表”等一次性提醒。

角色状态依据私聊里的明确反馈变化。“这次帮到我了”“这次回答不对”影响心情和多巴胺。
“我喜欢和你聊天”“我不喜欢这种相处方式”也会改变长期好感。心情以 6 小时为半衰期回到中性，
多巴胺按实际反馈与预期的差更新，以 35 分钟为半衰期回到中性。没回复不记反馈。
`/life status` 可查看三项数值，普通聊天只在当前请求中收到定性的表达提示，群聊、定时执行和主动消息不读取这些提示。

### 每日自动推进

确认普通模型和 AstrBot 当前会话的联网搜索可用，再开启 `web_search_enabled` 和 `auto_enabled` 并重载插件。
公开默认配置保持关闭。每天上海时间 `auto_hour` 之后，插件每分钟检查一次：已有目标、可用预算、免打扰结束、
聊天冷却结束且没有在途活动时，从现有候选中优先选择有新来源的目标，执行一轮检索和研究。
没有本地资料的已有目标也可先联网检索，不会自动新建目标。

当天已经有手动或自动研究，就不再自动启动。失败、中断、没有新资料也占用当天自动机会，重载、重启后不重试；
错过的日期不补跑。手动 `run` 仍受现有预算控制，严格 `trial_mode` 额外限制全部活动每天一轮。
`stop`、目标的手动暂停、取消和搁置均会阻止对应自动活动，不会自行解除。

每轮最多调用一次选定的 AstrBot 内置搜索工具，支持 AnySearch、Tavily、BoCha、Brave、Firecrawl、Baidu AI Search、Exa。
沿用当前会话的供应商和凭据，不开放设备、发送或任意工具。搜索查询只由目标标题和下一步构成，不附聊天历史。
最多保存三条公开 HTTP(S) 地址的非空摘要，并记录 URL、标题、查询和检索时间。
摘要中的指令视为资料；结论应区分来源陈述、推断和待核实，版本或出处不明时说明限制。
检索工具调用、超时、失败和没有新资料会保留记录；只有真正产生新来源的研究才视为进展。
搜索供应商可能自行重试或计费，搜索费用不计入模型调用次数；整轮仍受活动时间预算限制。

`share_enabled` 保持独立控制：关闭时通过聊天或 `/life` 看结果，开启时只在有进展后尝试分享，并沿用共享消息额度。
`/life status` 保留原有额度字段，并在 `research` 中显示实时执行器、功能开关和调度问题。
主人在配置的私聊中说“现在就查”并给出主题时，可用同一搜索配置即时查一次公开资料。短句会尝试接续最近明确的查询主题，歧义时请补上主题。
追问“给我个准确结果”时，若上一道问题对应唯一已联网查过的研究主题，或上一条明确要求查公开资料，会在本轮检索。
回复使用本次检索回执，并说明结论适用的条件。同一消息重复处理时复用回执。即时检索与研究任务分别记录，推进既有目标使用 `/life run` 或每日调度。

聊天只在询问研究或追问研究结果时附上研究资料。已经完成的检索、目标状态和计划中的下一步按各自记录说明。

### 2. 四步体验：研究《我的世界》新手开局

用主人 QQ 私聊机器人，下面每个代码块作为一条普通文字消息发送，不使用引用或转发。 示例直接使用目标名称，省去填写
ID；如果存在同名歧义，就用 `/life` 返回的完整目标 ID。

**第一步：创建目标。**

```text
/life new 体验我的世界开局 | 想了解新手第一天怎么玩 | 根据资料整理三步开局建议 | 阅读新手资料
```

收到“目标已记录或复用同主题记录”即可。这条命令依次填写：标题、理由、结束条件、下一步。

**第二步：提供一小段体验资料。**

```text
/life source 体验我的世界开局 | 《我的世界》生存模式中，木头可以制作木板和工作台，工作台能制作更多工具。新手第一天可以先准备基础工具，再搭建临时庇护所，并记住庇护所的位置。
```

应收到资料已保存及经历 ID。`source` 接收资料正文；只发链接不会自动抓取网页。

**第三步：研究一次。**

```text
/life run 体验我的世界开局
```

“已开始”表示启动成功，尚不代表研究完成。等待一会儿，用下面的命令查看状态：

```text
/life
```

目标不再显示“运行未结算”后，再进行下一步。若显示暂停或待核实，先处理提示或查看 AstrBot 日志。
研究期间普通聊天会请求停止后台，因此先等这一轮结束。

**第四步：像平时一样问它。**

> 你刚才研究《我的世界》有什么收获？用三步说明新手开局建议，再说说下一步准备研究什么，并给出来源。

回答应对应刚才提供的资料和保存的进度。它只研究了文字资料，不能据此声称已经进入游戏操作。
下次补充资料时继续对同一个目标使用 `source`，然后再手动 `run`，即可体验接着研究。

### 3. 常用命令

下表中的 `目标` 可替换为唯一的完整名称或目标 ID；`经历ID` 使用资料保存或经历查询返回的标识。
命令中的分隔符是普通竖线 `|`，左右各留一个空格；整条命令最多两千字。

| 想做什么                     | 发送内容                                              |
|------------------------------|-------------------------------------------------------|
| 查看目标与下一步             | `/life` 或 `/life list`                               |
| 查看当天额度和全局暂停状态   | `/life status`                                        |
| 给某个目标补充资料           | `/life source 目标 \| 资料正文`                       |
| 指定目标研究一步             | `/life run 目标`                                      |
| 查看候选及最近选择理由       | `/life candidates`                                    |
| 让它从候选中选一个并研究     | `/life pick`，也会占用一轮活动及模型额度              |
| 暂停／允许该目标继续         | `/life pause 目标` ／ `/life resume 目标`             |
| 修改下一步                   | `/life adjust 目标 \| 新的下一步`                     |
| 给建议                       | `/life feedback 目标 \| 建议内容`                     |
| 纠正一条经历                 | `/life correct 经历ID \| 纠正后的说法`                |
| 暂时搁置                     | `/life shelve 目标 \| 理由`，需要明确 `resume` 才继续 |
| 取消／放弃目标               | `/life cancel 目标` ／ `/life abandon 目标 \| 理由`   |
| 重开已完成、取消或放弃的目标 | `/life reopen 目标 \| 理由`                           |
| 查看双方的倾向记录           | `/life interests 目标`                                |
| 明确记录主人偏好             | `/life prefer 目标 \| 喜欢或不喜欢 \| 你的真实原话`   |
| 保存指定经历到长期记忆       | `/life remember 经历ID`，需要开启记忆桥接             |
| 查询相关经历                 | `/life recall 关键词`；长期记忆不可用时可回查本地记录 |
| 停止并禁止后续活动           | `/life stop`                                          |
| 允许后续手动启动活动         | `/life allow`，不解除目标自身的手动暂停               |
| 核对异常中断记录             | `/life recover`，不重新执行旧活动或重复发送消息       |

暂停后继续、允许活动和重开目标，都只改变可运行状态；之后手动 `run`、`pick` 或等待已开启的每日推进。
普通聊天用于讨论；建议、偏好和目标调整请用明确命令保存。只有唯一未结束目标时，
也可以直接发送“暂停这个目标”“继续这个目标”或“取消这个目标”。

**确认完成**需要你核对结束条件，并引用最近笔记中的有效经历，格式为：

```text
/life complete 目标 | 结束条件原文 | 经历ID1,经历ID2 | 完成依据
```

结束条件应与创建目标时的一致，经历标识用英文逗号分隔。完成依据被纠正后，需要重新核验。

### 4. 常见问题

| 提示或现象                               | 怎么处理                                                                                                                               |
|------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| 命令没有生效                             | 检查总开关、主人完整会话标识及是否为主人直接私聊；使用普通文字发送                                                                     |
| “试运行当天已开始过一轮”                 | 这是 `trial_mode` 的启动次数限制，与剩余模型次数分开计算。失败、中断和重启不退名额；正式观察等下一上海日期，手动体验可关闭此开关后重载 |
| “后台已暂停或仍在聊天冷却期”             | 用 `/life status` 核对状态；全局暂停用 `allow`，目标暂停用 `resume`；普通聊天后等待冷却结束，默认五分钟                                |
| “当前处于现有免打扰时段”                 | 等待允许活动的时段，不因手动研究绕过免打扰                                                                                             |
| 模型返回 `402 / Insufficient Balance`    | 检查当前模型 API 账户余额；普通聊天恢复后再尝试研究，严格试运行的失败仍占当日名额                                                      |
| “当前没有符合条件的候选”                 | 用 `candidates` 检查，补充有效资料，或明确继续已暂停目标；没有合适目标时会等待                                                         |
| 提示未结束目标已达上限                   | 先查看现有目标，明确取消、放弃或确认完成不再推进的目标；搁置仍占名额                                                                   |
| “已开始”后没主动发研究结果               | 检查目标状态，结束后通过普通聊天询问；`share_enabled` 关闭时不会主动分享                                                               |
| 记忆显示“结果待核对”或查询只返回本地经历 | 本地记录仍保留，但不能算长期记忆已保存并召回；先查询核验，未知结果不重复写入                                                           |

### 5. 实机验收与核对

在源码根目录核对安装状态，或查看已有试运行的记录。`<trial_id>` 对应运行目录下 `run/life_trials/` 的记录目录名。

```powershell
python tools/life_trial.py preflight
python tools/life_trial.py report --trial-id <trial_id>
python tools/life_trial.py snapshot --trial-id <trial_id>
```

记忆保存超时后先用 `python tools/life_trial.py memory-status` 查看写入状态，再用
`python tools/life_trial.py recall` 核对是否能召回。一次未命中仍按待核实处理，直到有可靠依据确认写入结果。
待核实期间保留原账本，以同一条经历核对。

实机验收分别核对研究完成和来源、长期记忆保存与召回、QQ 实际收件。跨日继续、前台打断、在途重启和限频观察
各自需要现场证据。用 `snapshot` 保存检查点，用 `report` 查看观察条件和记录天数，最终验收由人工核对。
改动影响既有结论时重新验证对应场景。
