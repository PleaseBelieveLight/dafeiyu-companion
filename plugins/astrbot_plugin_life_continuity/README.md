# 大肥鱼自主生活

让大肥鱼有一本可以接着写的“目标本”和“经历本”：记下准备做什么、研究到了哪里， 下次继续同一个目标，并在聊天时说清自己的进展。

## 插件是什么

这是大肥鱼项目自行维护的 AstrBot 插件，插件名为 `astrbot_plugin_life_continuity`。 目前面向 **配置的主人
QQ 私聊**，主要活动是研究主人提供的文字资料、整理笔记。研究复用当前会话的模型，
使用简短的资料研究协议与角色身份，会消耗模型 API 额度；对外聊天继续使用所选人格。

当前由主人手动启动，每次推进一个有限步骤。目标和进度保存在本地，重载或重启后仍可查询；
异常中断的目标先暂停，核对后再继续。目前的研究流程只读取提供的资料，不自动打开网页或操作游戏。

## 能做什么

- **管理目标**：记录研究主题、理由、结束条件和下一步，最多保留三个未结束目标，搁置也占名额。
- **研究并留笔记**：根据资料记录发现、待核实问题、来源和下一步；完成一轮不代表整个目标完成。
- **聊天接上进度**：可以问“最近在忙什么”“上次做到哪了”，让它根据已有记录回答。
- **选择和调整方向**：从有资料的候选中选择目标，记录理由；分别保存自己的研究倾向和主人明确表达的偏好。
- **由主人控制**：暂停、继续、调整、纠错、搁置、放弃或确认完成，保留已有发现和修改记录。
- **可选记忆与分享**：显式保存经历到 LivingMemory，或在研究后主动分享摘录；两者都有独立开关。

## 怎么用

### 1. 打开配置

本项目的安装和部署更新会复制此插件。在运行机器打开
[AstrBot 管理后台](http://127.0.0.1:6185)，进入插件管理，找到“大肥鱼自主生活”，编辑配置。

| 配置项             | 含义                                 | 手动体验时怎么设置                                                           |
|--------------------|--------------------------------------|------------------------------------------------------------------------------|
| `enabled`          | 总开关                               | 开启                                                                         |
| `owner_scope`      | 主人完整私聊会话标识                 | 填写实际会话标识，格式为 `平台实例ID:FriendMessage:主人QQ号`，不能只填 QQ 号 |
| `activity_enabled` | 允许单次研究和目标选择               | 开启                                                                         |
| `trial_mode`       | 严格试运行，每个上海日期最多开始一轮 | 手动体验可关闭；正式限频观察时开启                                           |
| `memory_enabled`   | 允许显式调用长期记忆                 | 初次体验可关闭；需要时再开启，并核验 LivingMemory 的会话隔离                 |
| `share_enabled`    | 研究后主动分享进展                   | 初次体验可关闭，通过聊天查看结果                                             |

公开默认配置的开关均关闭，主人会话留空。 **保存配置后重载插件。**
保留项目自带的主动聊天插件及发送适配，它们用于核验免打扰和共享消息额度；关闭研究分享时也需要。
研究前先确认普通模型聊天可用，并避开免打扰时段；普通聊天后默认冷却五分钟。

关闭 `trial_mode` 后，活动时间、模型调用次数、消息额度和免打扰限制仍然生效，也不会开启自动周期。
默认每日后台活动累计十分钟、模型调用二十次，主动分享与既有主动聊天合计每天一份。 这些是本插件的统计范围，不是全部
API 消耗的账单。

### 2. 四步体验：研究《我的世界》新手开局

用主人 QQ 私聊机器人，下面每个代码块作为一条普通文字消息发送，不使用引用或转发。 示例直接使用目标名称，省去填写
ID；如果存在同名歧义，就用 `/life` 返回的完整目标 ID。

**第一步：创建目标。**

```text
/life new 体验我的世界开局 | 想了解新手第一天怎么玩 | 根据资料整理三步开局建议 | 阅读新手资料
```

收到“目标已记录或复用同主题记录”即可。这条命令依次填写：标题、理由、结束条件、下一步。

**第二步：提供一小段体验资料。**

```text
/life source 体验我的世界开局 | 《我的世界》生存模式中，木头可以制作木板和工作台，工作台能制作更多工具。新手第一天可以先准备基础工具，再搭建临时庇护所，并记住庇护所的位置。
```

应收到资料已保存及经历 ID。`source` 接收资料正文；只发链接不会自动抓取网页。

**第三步：研究一次。**

```text
/life run 体验我的世界开局
```

“已开始”表示启动成功，尚不代表研究完成。等待一会儿，用下面的命令查看状态：

```text
/life
```

目标不再显示“运行未结算”后，再进行下一步。若显示暂停或待核实，先处理提示或查看 AstrBot 日志。
研究期间普通聊天会请求停止后台，因此先等这一轮结束。

**第四步：像平时一样问它。**

> 你刚才研究《我的世界》有什么收获？用三步说明新手开局建议，再说说下一步准备研究什么，并给出来源。

回答应对应刚才提供的资料和保存的进度。它只研究了文字资料，不能据此声称已经进入游戏操作。
下次补充资料时继续对同一个目标使用 `source`，然后再手动 `run`，即可体验接着研究。

### 3. 常用命令

下表中的 `目标` 可替换为唯一的完整名称或目标 ID；`经历ID` 使用资料保存或经历查询返回的标识。
命令中的分隔符是普通竖线 `|`，左右各留一个空格；整条命令最多两千字。

| 想做什么                     | 发送内容                                              |
|------------------------------|-------------------------------------------------------|
| 查看目标与下一步             | `/life` 或 `/life list`                               |
| 查看当天额度和全局暂停状态   | `/life status`                                        |
| 给某个目标补充资料           | `/life source 目标 \| 资料正文`                       |
| 指定目标研究一步             | `/life run 目标`                                      |
| 查看候选及最近选择理由       | `/life candidates`                                    |
| 让它从候选中选一个并研究     | `/life pick`，也会占用一轮活动及模型额度              |
| 暂停／允许该目标继续         | `/life pause 目标` ／ `/life resume 目标`             |
| 修改下一步                   | `/life adjust 目标 \| 新的下一步`                     |
| 给建议                       | `/life feedback 目标 \| 建议内容`                     |
| 纠正一条经历                 | `/life correct 经历ID \| 纠正后的说法`                |
| 暂时搁置                     | `/life shelve 目标 \| 理由`，需要明确 `resume` 才继续 |
| 取消／放弃目标               | `/life cancel 目标` ／ `/life abandon 目标 \| 理由`   |
| 重开已完成、取消或放弃的目标 | `/life reopen 目标 \| 理由`                           |
| 查看双方的倾向记录           | `/life interests 目标`                                |
| 明确记录主人偏好             | `/life prefer 目标 \| 喜欢或不喜欢 \| 你的真实原话`   |
| 保存指定经历到长期记忆       | `/life remember 经历ID`，需要开启记忆桥接             |
| 查询相关经历                 | `/life recall 关键词`；长期记忆不可用时可回查本地记录 |
| 停止并禁止后续活动           | `/life stop`                                          |
| 允许后续手动启动活动         | `/life allow`，不解除目标自身的手动暂停               |
| 核对异常中断记录             | `/life recover`，不重新执行旧活动或重复发送消息       |

暂停后继续、允许活动和重开目标，都只改变可运行状态，实际研究仍需手动 `run` 或 `pick`。
普通聊天用于讨论；建议、偏好和目标调整请用明确命令保存。只有唯一未结束目标时，
也可以直接发送“暂停这个目标”“继续这个目标”或“取消这个目标”。

**确认完成**需要你核对结束条件，并引用最近笔记中的有效经历，格式为：

```text
/life complete 目标 | 结束条件原文 | 经历ID1,经历ID2 | 完成依据
```

结束条件应与创建目标时的一致，经历标识用英文逗号分隔。完成依据被纠正后，需要重新核验。

### 4. 常见问题

| 提示或现象                               | 怎么处理                                                                                                                               |
|------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| 命令没有生效                             | 检查总开关、主人完整会话标识及是否为主人直接私聊；使用普通文字发送                                                                     |
| “试运行当天已开始过一轮”                 | 这是 `trial_mode` 的启动次数限制，与剩余模型次数分开计算。失败、中断和重启不退名额；正式观察等下一上海日期，手动体验可关闭此开关后重载 |
| “后台已暂停或仍在聊天冷却期”             | 用 `/life status` 核对状态；全局暂停用 `allow`，目标暂停用 `resume`；普通聊天后等待冷却结束，默认五分钟                                |
| “当前处于现有免打扰时段”                 | 等待允许活动的时段，不因手动研究绕过免打扰                                                                                             |
| 模型返回 `402 / Insufficient Balance`    | 检查当前模型 API 账户余额；普通聊天恢复后再尝试研究，严格试运行的失败仍占当日名额                                                      |
| “当前没有符合条件的候选”                 | 用 `candidates` 检查，补充有效资料，或明确继续已暂停目标；没有合适目标时会等待                                                         |
| 提示未结束目标已达上限                   | 先查看现有目标，明确取消、放弃或确认完成不再推进的目标；搁置仍占名额                                                                   |
| “已开始”后没主动发研究结果               | 检查目标状态，结束后通过普通聊天询问；`share_enabled` 关闭时不会主动分享                                                               |
| 记忆显示“结果待核对”或查询只返回本地经历 | 本地记录仍保留，但不能算长期记忆已保存并召回；先查询核验，未知结果不重复写入                                                           |

当前版本仍在实机联调，正常研究闭环、长期记忆保存后召回和真实跨日继续尚待完整验收。 研究成功、记忆保存、记忆召回与
QQ 实际收到消息分别判断，以实际记录为准。
