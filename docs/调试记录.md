# 模型请求与运行调试记录

用于核对“项目最终给模型发了什么”，以及这次回复经过了哪些处理。
首次部署默认关闭；部署更新保留已有开关，不会替用户打开。开启后从下一次请求开始记录，不能补回历史请求。

## 开关与查看

在项目根目录运行：

```powershell
python tools/launch.py request-trace on
python tools/launch.py request-trace status
python tools/launch.py request-trace latest
python tools/launch.py request-trace list --limit 20
python tools/launch.py request-trace off
```

`latest` 输出最新请求查看页的本地路径；尚无请求时输出总览页路径。
总览固定在运行目录的 `astrbot/data/plugin_data/dafeiyu_context/request_traces/index.html`，可用浏览器打开。
开关对后续请求生效，不需要为开关本身重启服务。关闭保留已有记录。

查看页包含来源、模型、时间、HTTP 状态、耗时、用量和模型结果。本轮输入直接展开，系统提示、历史上下文和工具定义默认折叠。
图片在页面内预览，Base64 不铺在正文里；原始 JSON 中的图片数据仍完整保留。页面不使用外部脚本或样式服务。

## 实际捕获位置

记录点位于 HTTPX 发送请求前，此时模型 SDK 已完成 JSON 序列化及 `extra_body` 合并。
保存的是实际请求体字节，包含最终系统提示、实际传入的历史、临时片段、图片、工具定义和参数。
导出时核验 SHA-256，保持字节一致；HTML 页面是便于阅读的呈现，不代替原始 JSON。

```powershell
python tools/launch.py request-trace export --latest
python tools/launch.py request-trace export --id 记录ID
```

命令输出解压后的 JSON 路径。导出文件放在 `request_traces/exports/`，由用户自行保留或删除。
如果记录失败、客户端不支持当前捕获方式，或单次请求体超过存储预算，运行事件会标注原因，正常聊天继续；不会用猜测拼接一份“原文”。

## 来源与其它日志

覆盖项目接入用量统计的 OpenAI 兼容 Chat Completions 调用，包括普通和流式请求。
工具循环、框架重试分别记录每次实际出站请求。来源标注包括：

| 来源 | 含义 |
|------|------|
| 普通聊天 | 面向用户的聊天生成 |
| 图片转述 | 主流程中的备用图片描述 |
| 上下文摘要 | 较早对话的压缩摘要 |
| 长期记忆 | LivingMemory 的总结、记忆处理 |
| 自拍规划 / 自拍理解 | 自拍场景规划、成图内容理解 |
| 主动消息 / 自主研究 | 主动聊天和自主生活调用 |
| 表情包处理 / 浏览器助手 | 表情包插件和独立浏览器助手中的聊天模型调用 |

每条请求有请求 ID、调用 ID；QQ 会话处理还有独立的轮次 ID，用于关联同一轮中的多次模型调用和运行事件。
运行事件记录已放行消息的类型、工具开始/结束、工具结果状态、QQ 成功投递及本轮结束情况。
消息内容以完整模型请求为准，运行事件不重复抄录聊天正文、工具参数或 QQ 身份。

- `requests/<记录ID>/request.json.gz`：压缩保存的完整 HTTP JSON 请求体。
- `requests/<记录ID>/meta.json`：来源、关联 ID、校验值、用量、HTTP 状态和异常类型。
- `requests/<记录ID>/response.json.gz`：普通调用的 SDK 响应对象。
- `requests/<记录ID>/response.jsonl.gz`：流式调用逐块保存的 SDK 事件，不是原始 SSE 字节抓包。
- `events/*.jsonl`：带来源与关联 ID 的运行事件；总览显示近期事件。
- 其它服务本身的详细日志仍在运行目录 `logs/`；未由本功能复制、清理或替换。

TTS、生图、视频、Embedding 和任意第三方 HTTP 请求不属于完整请求体捕获范围；相关工具的开始、结束和结果状态仍可出现在运行事件中。
只记录 HTTP 状态和异常类型，不复制可能回显鉴权信息的异常文本。

## 保存范围与容量

开关和容量配置在运行目录的 `astrbot/data/plugin_data/dafeiyu_context/request-trace.json`，
默认位于项目下的 `.local/`（见[目录说明](../scripts/README.md#本地运行与数据目录)）。
默认保留最近 7 天、最多 1,000 条请求，记录与事件预算为 512 MiB；开启时可调整：

```powershell
python tools/launch.py request-trace on --keep-days 7 --max-mb 512
```

写入新记录时清理本记录器可识别的旧记录和事件；不清理聊天数据库、记忆、备份或其它服务日志。
正在进行的请求受到保护，容量可能短暂超出预算。手动导出的 `exports/` 不在自动清理范围内。

记录不包含鉴权请求头、API Key 配置、请求地址查询参数。
请求正文、历史、模型结果和图片本身仍是私人资料，只存放在独立运行目录，不进入 Git、源码发布包或普通终端日志。
