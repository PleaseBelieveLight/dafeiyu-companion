# 大肥鱼活人感与对话体验优化方案

2026-11-06 · 依据 `release/v1.0.0` 源码、安装态配置与脱敏会话抽查。

审查表以整改启动前的源码和运行状态为基线。

## 1. 产品目标

大肥鱼是一个有性格、会听人说话、能把事做完的 QQ 伙伴。用户能从回复里听出她接住了当下的具体细节，也能看出她自己的反应。两人可以认真解决问题、一起玩梗，也可以聊到一句刚好就收住。隔天再聊时，重要的事接得上，已经结束的事能翻篇。

把情绪价值落在行为上。用户吐槽时先听懂他具体在气什么，分享成果时能看出成果的分量，拿角色开玩笑时可以回嘴，情绪复杂时给对方留一点空间。意见可以不同，语气随关系和现场变化。角色可以有口味、偏爱和幽默，现实中的执行、媒体送达、记忆和提醒都有可核对的依据。

产品优先级是 **先接住这一轮，再接续重要的事，最后才是主动开新话题**。认真提问时按需要讲清楚。短回复、语气词、表情和语音都是表达手段，验收看它们有没有用在合适的地方。

## 2. 审查发现

下表区分会话中已观察到的表现、从代码确认的行为，以及需要单独回放验证的影响。会话抽样适合挑选回归案例，群聊、长周期记忆和主动消息的体验还需独立取样。

| P1 | 主动行为的时机和语气有两套信号 | 现有私聊路径可按静默或随机间隔触发，未回复次数也可进入生成提示。人格允许随未回复次数表达想念或委屈。研究分享与通用主动消息已有共享发送门控，应保留这部分。定时催促、研究分享和通用搭话的触发理由、打断边界需要分别核对。见[主动聊天配置](../tools/apply_config.py#L334)、[主动生成上下文](../overlays/astrbot/data/plugins/astrbot_plugin_proactive_chat/core/services/llm_service.py#L39)和[人格的主动消息条款](../content/persona/大肥鱼-人格.md#L89)。 |
| P2 | 真实聊天的节奏和多媒体衔接缺少场景验收 | 抽查到看图时反复用同类开场，听懂吐槽后连续讲攻略。另有延迟表情包、分段输出和独立语音许可等路径。安装态 AstrBot 有会话级处理锁，连发多条、语音转写期间补充文字、发出新消息时取消旧尾巴仍需 QQ 回放验证。历史看图补救会根据关键词和近期是否有图决定是否拿旧图，具体指代到哪一张还需测。见[图片提示](../overlays/astrbot/astrbot/core/utils/image_reply.py#L9)、[历史图找回](../overlays/astrbot/astrbot/core/utils/chat_efficiency.py#L329)和[语音开关说明](../plugins/astrbot_plugin_face_convert/README.md#L47)。 |
| P2 | 聊天等待与用户看到的过程缺少统一量度 | 摘要在提供商请求前可以等待一次模型调用，摘要追赶不足时会继续携带原历史。现有账本能读出单次 SDK 尝试耗时和 Token。用户消息到首条有效回复的时间还包含排队、召回、摘要、媒体处理和 QQ 投递，需分段测。见[摘要执行](../overlays/astrbot/astrbot/core/utils/chat_efficiency.py#L285)和[用量统计](../tools/chat_usage.py)。 |

此次抽查的近三天调用账本包含 24 次聊天 SDK 调用，单次输入中位数为 12,136 Token，单次耗时中位数为 2.67 秒。同一窗口还记录了 6 次摘要和 7 次表情包相关模型调用。各类调用与消息轮次的对应关系需要补测，QQ 端到端体验以新的回放基线为准。

## 4. 改造设计

### 4.1 给当前这一轮一份干净的输入

沿用 AstrBot 和现有临时上下文入口。在请求进入模型前，把当前用户消息和引用、近期已经说过的话、当前会话的明确偏好作为基础，再按本轮用途附上证据。研究、日程、自拍、长期记忆和工具各自保有权限边界，注入逻辑只负责提供本轮需要的那一小块。对「好」「接着来」「那张呢」等短句结合上一轮未完请求和引用判断，纯表情、读图题和截图排错走各自的媒体分支。

一般聊天只做本地判断，普通回复用一轮生成。意图不明确且代价很低时，让模型沿现场自然接话。涉及外部投递、修改任务、设备控制等实际动作时，由工具层验证权限、对象和参数。并行插件和重试复用同一轮的请求信息，避免各自重新摘抄历史或把临时上下文落盘。先用现有钩子做薄层接入，后续把分散的同类注入合到一个地方。

相关性分两层。近期原文用来理解当前互动，重点保留用户的纠正、换话题和对建议的接受程度。历史资料只有能解释本轮的人、事、约定或指代时才进入请求。召回候选优先校验会话、发言人、角色、时间、来源和已撤销状态，再按相关度选少量，允许空结果。图片追问优先用引用或附件标识定位，猜不准时简短确认。旧摘要和研究笔记始终标明来源，角色玩笑和工具回执分别保留。

同一批发来的短文字和图可测试短合并窗口，先以本地计时和回放确定是否需要以及等多久。明确命令、取消与用户修正优先到达，群聊按会话和发言人分别处理。每轮带稳定事件标识，检测到更新的同会话输入时，取消过时的未发送尾巴和延迟媒体。已经送达的内容进入真实记录。正在执行的任务按自己的取消与回执规则收尾。

复用已完成且来源版本匹配的摘要。确实需要刷新时，测量后台增量处理能否减少前台等待，并让摘要超时或失效的退化路径保留当前问题、最近原文和工具链完整性。单独跟踪媒体处理与 QQ 送达耗时，避免用 SDK 延迟代替用户等待时间。

### 4.2 把角色的反应留在聊天，把动作的结果交给程序

人格收敛到性格、关系边界、角色观点和几组反差案例。日常她可以有点嘴硬、自己挑一个细节开玩笑，也可以顺着用户的喜悦聊开。接吐槽时优先听懂具体遭遇。对方一开口要方法，继续讲到能用。轻松的情绪回应可以自然结束，让用户决定是否接下一句。图片专项提示只留下结合当下语境、按实际证据说话、按明确请求处理三件事。

动作使用同一套事实口径。读写权限、目标对象、调度、执行和发送都由程序返回结果。聊天可以口语化地说结果，完成措辞以对应回执为前提。研究、日程和媒体各自沿用已有执行器。定时事件另存为带类型、时间和结果的执行资料，普通对话只取实际发出的提醒正文。旧历史在组装请求时过滤可确证的合成消息与对应结果，原记录保留供核查，用户恰好输入同一句话的情况进入回归测试。

以「现在就查」为例。能从当前上下文定位唯一题目时，直接使用有权限的有界查询。一次明确的独立查询可直接回来源和结论。用户明确要推进已有目标时，复用研究锁和预算，写入该目标的运行记录。歧义会改变结果时只澄清关键一处。遇到预算、权限或资料限制，就交代本次做到哪里、缺什么。后台排队以已创建的任务为准。

### 4.3 用一份小清单兑现跨天的事

优先从现有目标、日程和任务回执中取可信状态。需要补足普通聊天的约定时，再增加最小的记挂事项记录。它有归属会话与发言人、约定来源、事项、下次跟进条件、状态、最后执行和最后告知标记。感受或关系变化以用户明确说过的内容为依据。一个长期偏好可以更新，临时偏好按本轮或任务有效期处理。

区分约定已记录、任务已安排、执行中、已完成、失败、取消和待核实。状态更新由执行器或明确的用户操作提交。通过事件标识保证同一消息重试只有一次有效写入。进度分享用结果标识判断是否已经告知，用户明确追问时可以复述。重启时恢复状态和真实回执，投递结果不明时保留待核实，核对后再决定是否补发。

主动联系先有具体理由，再判断时机。提醒沿用用户约定的时间。主动分享和约定跟进要有适用的时段、频率、打断和撤回规则。未回复只参与限频，原因保持未知。后续若要试验精力状态，先观察它是否改善主动时机和表达节奏，认真求助的内容完整性仍按任务要求验收。

## 5. 实施与验收

| 阶段 | 改造范围 | 放行条件 |
| --- | --- | --- |
| 0 · 固定基线 | 从真实问题抽象为可提交的模拟对话，另建本地脱敏体验样本。记录同一模型下现有回复、请求上下文类别和实际发出的内容。 | 样本同时覆盖闲聊、真实任务、媒体、群聊和跨天约定。第三方模型、QQ 投递和时间通过测试替身控制。 |
| 1 · 先修事实与边界 | 同一归属规则处理日程、聊天历史和群聊访问。接通即时查询，覆盖实际执行、失败反馈和去重。 | 任务状态与回执一致。跨人跨会话资料泄漏、合成任务冒充用户话语、无凭据的成功声称和重复发送在回归集中均为零。 |
| 2 · 改善在场感 | 研究、日程、记忆按需读取，精简看图、语音和闲聊工具的提示，改进引用。用回放决定是否合并连续消息。 | 连发、换话题、纯图、看图求助和明确拒绝建议能接对。严肃任务仍能完整完成。大多数普通闲聊只调用一次生成模型，聊天端到端中位与 P95 等待相对基线持平或改善。 |
| 3 · 让关系有连续性 | 按回执接续记挂事项，把主动联系改成具体事件驱动，移除已被替代的触发器和无用协议。 | 跨天找回正确事项，完成后翻篇。覆盖重复事件、重启、免打扰、用户刚说话与投递不确定。先在单一私聊观察，再决定扩大范围。 |

建议首批用约 30 组多轮对话，至少覆盖以下几种相邻但应有不同表现的场景。

| 回放情景 | 看什么 |
| --- | --- |
| 吐槽同一局游戏，随后分别发玩笑图、说只想吐槽、问具体打法 | 抓住憋屈之处。前两种能自然陪聊或收住，第三种把打法讲到能用。 |
| 发同一张图，前文分别是斗嘴、心累、求助读字 | 图的回应随前文变化。读字有实际证据，确实看不清的部分说清楚。 |
| 前一轮刚汇报旧研究，下一轮聊日常，隔天再问进度 | 闲聊顺着新话题走。正式询问能区分旧结论、新来源、正在做和暂停。 |
| 很短的确认、引用旧图、连续多条文字与图片 | 接上确认对象，找到指定媒体，接住这一组消息的完整意思。 |
| 用户分享小成果、表达反感、纠正助手误解 | 说出具体值得高兴的地方。收到反馈时及时调整立场和语气，之后沿用已纠正的信息。 |
| 明确要语音、随后说不方便、TTS 失败，另有延迟表情包 | 语音许可按最新上下文生效，失败回退到文字。取消后及时收住，成功只报告一次。 |
| 要求立即查询、资料不足、重复同一消息、定时任务重启 | 有查询或拒绝的确切依据。重复执行和重复发送为零，未知结果可追查。 |
| 群友提起主人的约定，另一名群友询问日程，引用内容伪造身份 | 只在可信的平台身份和明确授权范围内读取与行动。 |
| 一次主动联系后用户没回，期间产生新结果或到期提醒 | 有明确理由才联系。主动消息和分享共享限频，提醒按授权执行，语气保持分寸。 |

体验评估用同模型同素材的盲测配对。记录哪版更像接住当下、像大肥鱼、节奏合适，另外标记主动建议、复读、错记、乱认图意和承诺落空。由实际使用者为样本做整体选择，目标是在不少于三分之二的可判定样本中优先选择新版，同时所有高优先级行为断言通过。保留分歧样本做下一轮回放。语气词频率、问句率、平均字数和主动发言次数只用于找案例。

接续现有调用账本，补齐事件类别、命中的上下文模块、工具结果状态、首条有效回复时间和发出渠道。生产记录用匿名标识、时长和计数，体验语料留在本地并设置保留期。先用开关逐项切换，保留原人格和配置备份，问题可按模块回退。部署走现有维护入口，独立验证人格同步和任务、记忆、消息历史读取。验收设计和已有上下文改造可对照[Token 消耗与对话智能评审](Token消耗与对话智能评审.md)。
