# 自主生活阶段 1：持久化与部署基础

日期：2026-10-29。分支：`feat/life-continuity`。

本文保留阶段 1 交付时的能力和测试基线；后续聊天接口及 v2 数据迁移见[阶段 2 说明](自主生活阶段2交付说明.md)。

本阶段提供目标、经历、运行记录和简短笔记的存储基础，以及默认关闭的 AstrBot 插件入口。
验收面向临时安装和数据可靠性；实际运行目录尚未部署新插件，也未启用自主活动。
聊天上下文、记忆桥接、调度、预算和目标选择按[整体计划](自主生活行为与记忆机制开发计划.md)继续实施。

## 1. 基线与适配结论

- 开发前 43 项源码回归通过。沙箱首次执行有三项 Windows 临时目录重命名权限错误，
  在允许正常操作临时目录的环境重跑后通过，未修改原测试断言或跳过条件。
- 新插件为 `astrbot_plugin_life_continuity`，没有 B 站、PhoneMCP、模型或云端服务依赖。 使用标准库
  SQLite；目标、经历和在线备份设计参考上游，保持独立数据库身份和版本。
- AstrBot 的 `Star`、配置注入、`initialize/terminate`、`StarTools.get_data_dir` 为本阶段集成入口。
  插件尚未注册聊天钩子、Agent 工具或后台任务。
- 首个后续活动限定为有限问题研究和笔记续写。真实资料来源、设备锁、模型调用计数和
  全局主动消息节流仍需在接入执行前验证，本阶段不将它们标记为已完成。

## 2. 已交付内容

| 内容       | 行为                                                                           |
|------------|--------------------------------------------------------------------------------|
| 目标       | 保存来源、理由、结束条件、下一步、状态和检查点；原始请求指纹抑制重复创建       |
| 经历       | 事实与感想分别保存；按会话、目标、运行关联；同一来源幂等，纠错追加修订         |
| 笔记       | 追加不可覆盖的版本；要求当前会话、当前目标下有效的经历来源                     |
| 运行记录   | 原子记录开始与结束；单会话只允许一个进行中的运行；单轮完成不等于目标完成       |
| 并发保护   | 检查点和笔记使用预期版本，过期更新拒绝覆盖新数据                               |
| 数据库迁移 | 事务内创建结构与版本；已有可升级库先在线备份，涵盖已提交 WAL；失败回滚         |
| 数据异常   | 更高版本、其他应用的数据库、缺失结构和损坏数据库明确报错，不自动修补或清空     |
| 只读查询   | 缺库返回未初始化；不创建数据目录、不迁移、不恢复运行；默认只返回计数           |
| 默认关闭   | 缺少开关、开关为 false 或类型不正确时，不创建存储、不启动任务                  |
| 部署适配   | 复用安装器的项目插件复制步骤；配置和数据位于代码目录之外，重复复制保留已有内容 |

打开写入存储也不会自动恢复或重置运行中记录；异常中断恢复属于阶段 3。 数据库中保留的 `running`
仅是未结算状态，不能据此认定设备当前正在执行。 目前只有受信任的 Python 存储接口，没有通过 QQ
创建、更新或执行目标的入口。

## 3. 路径与配置

以下路径相对于通过 `tools/workspace.py` 解析的运行根目录：

| 路径                                                                   | 内容                           |
|------------------------------------------------------------------------|--------------------------------|
| `astrbot/data/plugins/astrbot_plugin_life_continuity/`                 | 安装后的插件代码及默认配置结构 |
| `astrbot/data/config/astrbot_plugin_life_continuity_config.json`       | AstrBot 管理的插件配置         |
| `astrbot/data/plugin_data/astrbot_plugin_life_continuity/life.sqlite3` | 目标、经历、运行与笔记         |
| 同一数据目录下 `schema_backups/`                                       | 迁移前的一致性 SQLite 备份     |

新增插件配置 `enabled` 默认 `false`。阶段 1 将它设置为 `true` 并重载插件，只初始化存储，
不产生自主活动。存储异常会记录错误并保持本功能不可用，不向聊天初始化传播异常。 更改配置后需要重载插件，卸载时关闭数据库连接。

当前只支持新建独立数据库，以及从空白 v0 数据库初始化到 v1；不直接导入旧 B 站插件的数据库。 现有 v1
重开时验证结构并保留全部状态。后续增加迁移时仍须先一致性备份再事务升级。

## 4. 只读查询

在私有项目根目录使用 Python 3.12 执行：

```powershell
python tools/life_state.py
python tools/life_state.py --scope "实际主人会话标识" --limit 20
```

默认使用独立运行目录，也支持已有的 `DAFEIYU_RUNTIME_ROOT` 环境变量。 不传 `--scope`
时仅返回数据库状态和各表计数；传入完整会话标识后返回该会话的有限记录。 查询不会调用 AstrBot、模型、QQ
或设备。数据库异常返回非零退出码，不伪装为没有数据。

SQLite 只读连接可能产生 WAL 的辅助文件；查询不修改数据库内容、结构或运行状态， 也不使用忽略 WAL
的读取方式，避免漏掉已经提交的进展。

- 目标、经历、笔记版本与检查点保存后重开；原始来源重复请求和内容冲突。
- 两个写入连接的旧版本覆盖保护；运行结束与检查点原子落盘。
- 会话、目标、运行和引用隔离；经历修订后拒绝使用旧来源新建笔记。

- 高版本、非本应用、损坏及不完整数据库拒绝打开；只读查询不初始化或恢复。

## 6. 部署与回退边界

新插件通过现有安装和部署更新流程复制，本次仅在临时目录验证，未重启或覆盖实际服务。 正式部署默认保持关闭；阶段
2 接入聊天，阶段 3 验证有界执行后再考虑开放周期。

回退前先关闭插件、释放连接并备份最新配置和数据库。当前代码目录与数据目录分离，
回退代码不回滚已经保存的数据；不兼容版本应拒绝写入。运行数据和备份不进入 Git。
