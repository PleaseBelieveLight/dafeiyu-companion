# 自主生活阶段 3：有界执行与恢复

日期：2026-10-29。分支：`feat/life-continuity`。插件版本：`v0.3.0`。

本阶段已完成本地实现与隔离集成验证，未部署到实际服务，未开启周期活动。
真实模型、QQ 和实际跨日验收仍待完成，不能将下面的离线验证视为实机验收通过。
前置核对见[阶段 0 清单](自主生活阶段0兼容清单.md)，整体安排见[开发计划](自主生活行为与记忆机制开发计划.md)。

## 1. 交付范围

主人先提供有限目标和文字资料，再显式触发一个研究步骤。代码调用 AstrBot 原生 Runner，
使用当前会话模型和人格，读取最多三份有效资料，每份最多两千字，保存实际读取范围。
结果须包含来源标识、想法、待核实问题和下一步，核验后追加一版笔记和检查点。
下一次可继续同一个目标；完成本轮步骤不等于整个目标已经完成。

本轮使用独立请求，不改聊天历史，也不修改共享 Provider。工具集合为空；没有网页、手机、
设备操作或公开发布入口。后台不运行正常聊天中的记忆、媒体等扩展钩子，避免产生未计量调用。
LivingMemory 仍由阶段 2 的显式命令桥接；研究笔记不会因此自动导出为长期记忆。

## 2. 开关与命令

配置仍在运行目录的 `astrbot/data/config/astrbot_plugin_life_continuity_config.json`。
`enabled`、`activity_enabled`、`share_enabled` 和 `memory_enabled` 均默认关闭，
`owner_scope` 默认留空。接口仅接受配置的主人 QQ 私聊中的直接文字。

| 命令 | 行为 |
| --- | --- |
| `/life new 标题 | 理由 | 结束条件 | 下一步` | 保存目标，尚不运行 |
| `/life source 目标ID | 资料正文` | 保存主人提供的资料、消息标识和来源归属 |
| `/life run 目标ID` | 在全部条件满足时，执行一次有限步骤 |
| `/life status` | 查询上海当天的预算和全局暂停状态 |
| `/life list` | 查看目标、状态和下一步 |
| `/life stop` | 持久化禁止后续活动，并请求停止当前执行 |
| `/life allow` | 允许后续手动触发，不开启周期，也不解除目标的手动暂停 |
| `/life recover` | 持有活动与投递租约后核对中断记录，不重放活动或消息 |
| `/life resume 目标ID` | 解除该目标的手动暂停，之后仍需显式 `run` |

暂停、取消、调整、反馈、纠正经历和记忆命令继续沿用阶段 2。
目标调整或来源纠正前先停止本轮；无法确认在途调用结束时拒绝调整。
每条命令最多两千字。重放同一运行消息不重复创建执行，同一消息标识不能跨目标复用。

## 3. 预算、免打扰与停止

| 配置 | 默认值 |
| --- | --- |
| `daily_minutes` | 每天十分钟 |
| `max_run_seconds` | 单轮上限三百秒 |
| `model_timeout_seconds` | 单次调用六十秒 |
| `max_model_calls_per_run` | 单轮十次模型调用 |
| `daily_model_calls` | 每天二十次模型调用 |
| `daily_shares` | 每天一份主动消息，自主分享与主动聊天合并 |
| `stop_timeout_seconds` | 等待在途调用结束五秒 |
| `chat_cooldown_seconds` | 前台聊天后冷却三百秒 |

首轮是一个只读步骤，监督时限取单轮上限和模型超时的较小值，默认最多六十秒；
当天剩余活动时间不足时继续缩短。停止后的等待另有上限。
模型调用前逐次持久化计数，原生 Runner 重试也经过此入口；禁用备用模型和额外摘要模型。
调用次数不等于供应商内部 HTTP 重试数或完整账单。只保存接口实际返回的 usage，缺失时保留未知。

已有主动聊天插件必须启用，并完整加载两个发送补丁，才能运行活动。
继承主人会话 `schedule_settings.quiet_hours`，无法读取、格式错误或处于免打扰时均拒绝新活动。
不会替用户覆盖已有设置。正常聊天会记录冷却并请求后台停止；停止或数据库异常不阻断普通聊天。

活动使用进程级文件租约，同一数据目录只能有一个执行者。取消请求不等于实际退出：
超过等待时限仍未结束时标为待核实，保留租约，禁止启动另一个执行者。
实际退出后释放租约，再由显式恢复核对状态；没有自动重试循环。

## 4. 持久化与恢复

数据库升级至 v3，新增活动控制、会话、时间、模型调用及共享投递账本。
v1、v2 升级先做一致性备份，事务失败回滚；只读管理查询不触发迁移或恢复。
预算按上海日期保存，跨午夜预留分摊到两天，模型和消息归属实际发起日期。
确认执行结束才退还已知未用时间；崩溃、时钟回拨或在途状态不明时保留预留消耗。

笔记、检查点、目标版本和运行状态在同一事务中保存。
引用必须来自本轮实际提供的有效资料；目标版本变化或来源被纠正后，旧结果不能覆盖新状态。
资料事实保留在来源记录，模型输出保留为想法及待核实部分，不能作为设备操作成功证据。

启动新活动或显式恢复时，先获得活动和发送租约，确认没有其他执行者，再核对旧运行。
重启遗留的执行标为中断，目标保持手动暂停，不自动继续；已取消目标不会被恢复复活。
恢复保留未知成本，未知投递不重发。正常步骤结束后的只读检查点可由下一条 `run` 继续。

## 5. 共享发送

开启总开关与单次活动开关后，指定主人会话的既有主动聊天也进入同一投递账本。
是否正在研究、是否开启笔记分享，不改变共享额度；其他会话及普通回复保持原流程。
显式命令回复不占主动额度。

发送前预留额度并记录稳定请求标识，同日相同正文也去重。
受控发送不分段，不在一次平台发送结果未知后换路径再发；超时或失败保留不确定记录并占用额度。
发送任务实际结束前保持独立发送租约，新活动不能抢先核对或重发。
正常返回只表示传输接口完成；不声称主人已收到或已读，`recipient_confirmed` 保持 false。

## 6. 验证记录与后续验收

- 134 项源码测试通过，包括上海日界分摊、持久化额度、重复触发、跨进程租约、
  超时及不响应取消的替身、前台停止、来源失效、事务回滚、v2 迁移和未知投递抑制。
- 在临时目录复制项目插件，使用真实 AstrBot 原生 Runner、事件、SenderService 和发送适配器，
  配合离线 Provider 与传输替身完成两轮研究，保存两版笔记；两次模型调用均记录 usage。
  自主分享占一份额度，已有主动聊天占另一份，第三次发送被拒绝；重开插件后记录和额度保留。
- 载入源码中的两个发送补丁后，73 项既有 SDK 运行回归通过，覆盖语音、媒体、自拍和音乐等路径。
  测试中的模型、下载与 QQ 传输均使用替身，没有部署源码补丁到实际运行服务。
- 发布检查、Python 编译及差异空白检查通过。当前基础 Python 没有 Ruff，未执行 Ruff 检查。

验证中修复了几类故障边界：命令处理和回复发送放在同一异常块会导致回执丢失后再次发送，
现改为处理完成后只发送一次；冷却持久化失败可能影响前台，现独立捕获并继续请求停止；
原主动发送入口的完整 context 假设不适合旧调用，现先检查可选接口，再决定是否接入额度。
受控路径另去除了结果未知后的发送兜底，避免重复投递。

后续先保持关闭状态部署并重载相关插件，再进行一次真实模型与 QQ 的单轮验收，记录
目标、来源、读取范围、笔记版本、预算及接口回执，并单独确认主人实际收到。
重启、实际跨日和真实 LivingMemory 保存召回仍须现场验证。阶段 4 的兴趣选择、搁置、
结束机制和阶段 5 的七至十四天限频观察尚未实施；当前没有低频周期入口。
