# 自主生活阶段 4：目标选择、兴趣证据与搁置

日期：2026-10-30。分支：`feat/life-continuity`。插件版本：`v0.4.0`。

后续部署和真实单轮结果见[阶段 5 记录](自主生活阶段5联调与试运行.md)。下文保留 v0.4.0 交付时的状态。

本阶段完成本地实现、源码回归及真实 SDK 的离线集成验证。没有部署、调用真实付费模型或向 QQ 发送消息。
真实单轮和跨日验收仍待完成，因此周期调度继续关闭。本阶段提供单次选择入口，
后续限频试运行见[整体开发计划](自主生活行为与记忆机制开发计划.md)。

## 1. 当前行为

主人可以指定目标执行，也可以让大肥鱼在已有候选内选择。代码先排除手动暂停、待核实、
已结束、缺少有效资料及尚不满足重开条件的目标，再按新来源、近期进展和有来源的倾向排序，
提供最多三个候选。模型只能选择其中一个或等待，保存候选快照及选择理由。 没有候选时直接记录等待，不调用模型，也不强行创建探索目标。

`pick` 的选择和研究使用同一个运行标识、执行租约、时间预留和模型账本；选择也消耗模型额度。
初始至少需两次可用调用额度，低于该额度时可明确指定目标直接 `run`。
选择后改变运行归属和保存选择记录在同一事务中完成；期间目标或来源发生变化，旧选择不能覆盖新状态。
停止、免打扰、聊天冷却、共享发送和未知结果规则沿用[阶段 3](自主生活阶段3交付说明.md)。

本轮不自动生成新目标。新探索仍由主人提供有限目标和资料；空闲与资料不足都可以等待。
模型选择不增加网络、设备、公开写入或代码修改权限，原生 Runner 仍使用空工具集合。

## 2. 去重与目标数量

新建和重开在写事务中检查同一会话最多三个未结束目标，搁置也占名额。
历史超额记录不删除；完成依据被纠正时先撤回完成状态，等待复核，期间不能通过新增目标扩大数量。

标题经全半角、大小写、空白和末尾常用标点规范化后判重。
`C`、`C++` 和 `C#` 等有意义的符号保持区别。这是标题去重，不宣称能识别所有语义重复。
不同消息再次创建同主题时返回已有记录，不覆盖旧理由，也不暗中重开已取消或已放弃的目标。
迁移保留历史同名记录，已有歧义时使用完整目标 ID。

## 3. 兴趣与进展的证据

机器人倾向和主人偏好分别保存，均带经历标识、归属、方向、时间及内容指纹。

- 机器人倾向仅取成功研究后返回的可选 `interest=-1/0/1`，关联本轮实际读取并引用的资料。
  它表示继续研究的倾向，不是客观事实，也不代表主人喜好。中性输出不新增兴趣证据。
- 主人偏好只由直接私聊中的明确 `prefer` 命令记录。普通建议、操作许可和模型推测不转换为偏好。
  最近两条有效建议随候选送给选择器参考，保留经历标识；纠正后仅提供当前版本。
- 同主题、同归属、同一份规范化内容只计一份证据；重复总结或复制成不同经历标识不增加权重。
  更正后无效的来源不计分。重新核对同内容可以更新失效的来源指向，保留原始时间，不刷新证据年龄。
- 展示与排序按 `方向 / (1 + 年龄 / 30天)` 计算参考分，查询时计算，不通过定时器改写历史。
  分数只影响候选参考顺序，不授权结束、取消、操作设备或推导其他主题的偏好。

进展采用保守的可核验标准：成功研究并引用了此前未读取的独立资料内容。 每份资料只统计本轮实际传入模型的前两千字；相同资料换消息标识，
或只改模型输出的摘要与问题措辞，均不算新证据。 补充的真实答复可作为新资料继续研究，不以模型自报“问题已解决”直接认定推进或完成。
新资料只表示取得了新的来源陈述，不代表其中观点已经被独立证实。

模型输出格式错误、依赖失败、预算拒绝、前台打断和等待均不计为无进展轮次。
成功笔记、实际尝试、倾向证据、连续计数与检查点在一个事务中保存。 没有新证据的复核不会主动分享一份改写后的笔记，避免把措辞变化当作进展。

## 4. 搁置、放弃与完成

首次成功读取新来源将连续无进展计数清零；之后连续三轮成功复核仍无新来源时：

- 自主目标进入 `shelved`，保留笔记、理由及至少二十四小时后的复查时间。
  复查时间已到且存在尚未读取的新来源，才能再次进入候选；只到时间或只改写旧来源均不满足。
- 主人指定目标进入手动暂停，等待明确指引。即使后来补充资料，也不自动解除暂停或取消目标。
- 主人明确 `shelve` 的目标同样保持手动恢复；复查时间不覆盖手动意愿。

`abandon` 必须来自主人明确评议并附理由，保留已有发现及来源，不因模型的一次负面倾向自动放弃。
已结束目标仅能通过明确 `reopen` 重开，仍受目标数量限制。

`complete` 要求主人确认当前结束条件的原文、提供最近有效笔记中的经历 ID，并写明依据。
代码核验当前目标、笔记和来源，保留笔记版本与完成依据；任意自然语言结束条件的语义仍由主人复核。
模型不能自行调用完成接口。完成依据后来被纠正时，撤回“已完成”并手动暂停，等待重新核验。

## 5. 主人命令

总开关和主人会话边界不变，活动开关仍默认关闭，没有新增周期开关。

| 命令                                                               | 用途                                             |
|--------------------------------------------------------------------|--------------------------------------------------|
| `/life pick`                                                       | 单次筛选、选择并执行一个有限研究步骤，允许等待   |
| `/life candidates`                                                 | 只读查询候选和最近选择理由                       |
| `/life interests 目标ID`                                           | 查看双方倾向的参考分、有效来源数量及生命周期状态 |
| `/life prefer 目标ID \| 喜欢或不喜欢 \| 主人原话`                  | 显式记录主人偏好                                 |
| `/life shelve 目标ID \| 理由`                                      | 手动搁置，不自动恢复                             |
| `/life abandon 目标ID \| 理由`                                     | 明确放弃并保留发现                               |
| `/life complete 目标ID \| 结束条件原文 \| 经历ID1,经历ID2 \| 依据` | 核对来源后明确完成                               |
| `/life reopen 目标ID \| 理由`                                      | 明确重开已完成、取消或放弃的目标                 |
| `/life resume 目标ID`                                              | 解除手动暂停或搁置，之后仍需显式触发             |

保留阶段 2、3 的其他命令及消息长度限制。生命周期变更前先停止在途执行，再读取新版本，
无法确认停止时拒绝变更。命令仅接收配置主人私聊中的直接文字，不能由引用、转发或模型工具执行。
同一触发标识不能换成另一个目标或另一种选择模式；选择前崩溃的触发也不重放。

聊天上下文包含少量选择理由、生命周期状态和分开归属的倾向摘要；记录仍按当前会话隔离。 显式导出偏好到
LivingMemory 时标明主人陈述，后台不自动导出，也不声称已经实际召回。

## 6. 数据与验证

数据库升级至 v4，新增目标档案、实际尝试、兴趣证据、选择和主人评议账本。 迁移前做一致性备份，保留 v1～v3
的目标、预算及投递状态；失败回滚，查询不迁移、不恢复。 旧记录不追认历史兴趣或进展。重启保留搁置、手动暂停、消耗和依据，不重放未知活动。

验证结果：

- 165 项源码测试在真实 Windows 8.3 短路径临时目录下全部通过，覆盖迁移、复核、去重、
  完成依据失效、主人边界、候选外输出、选择冲突、停止、重复触发和事务中断。
- 临时安装使用真实 AstrBot Runner、事件、SenderService 和发送适配器，配合离线 Provider 与发送替身，
  完成一次选择和两次研究，共三次计量模型调用，保存两版笔记；双方兴趣各保留一份来源。
  完成确认、明确重开及插件重开后的持久化验证通过；自主分享与原主动聊天继续共用两份测试额度。
- 发布检查、编译检查和差异空白检查通过。Ruff 在当前环境不可用，未执行。

额外修正了来源分类边界：仅根据 `owner_correction` 名称判断资料，会把纠正后的建议或偏好也当成研究来源。
现在追溯原始经历类型，只有原本属于真实资料读取的修订才进入研究候选。

以上是本地与离线结果，不代表真实模型、QQ、LivingMemory 或实际跨日验收通过。 下一步先在关闭状态部署并完成单次真实链路核验，再进入阶段
5 的限频观察；当前没有开放周期调度。
