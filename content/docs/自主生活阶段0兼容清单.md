# 自主生活阶段 0：基线与适配清单

核对日期：2026-10-29。阶段 1、2 已完成部分接口核对，本清单补齐其记录和进入阶段 3 的技术选择。
阶段 0 是接口与范围核对，不代表后台执行、预算、节流或真实活动已经实现和验收。

| 项目 | 核对结果 | 阶段 3 的选择 |
| --- | --- | --- |

| 持久化 | 阶段 1、2 已验证迁移备份、版本冲突、会话隔离和只读查询 | 新增结构继续版本化迁移，查询不触发恢复 |
| AstrBot Agent | 当前原生 `ToolLoopAgentRunner.reset/step_until_done` 可构造独立请求并取得 usage | 每次活动使用原生 Runner 和当前会话 Provider；不创建常驻 Agent |
| 人格 | 当前 PersonaManager 支持按会话、已有会话人格和配置解析生效人格 | 只读取当前人格，不改聊天历史或人格配置 |

| 手机及浏览器 | 手机有外部操作和串行控制边界；浏览器工具还会调用独立模型 | 首轮不使用这些工具，避免无法完整统计的嵌套调用及设备争用；后续接入需另验 |

## 2. 首个活动与执行入口

首个活动固定为研究主人明确提供的文字资料，并续写带来源的简短笔记。
资料须记录真实消息标识、原文及读取范围；模型推断与资料事实分开。
没有有效资料时不调用模型，不预填虚构浏览或设备经历。

阶段 3 只开放主人显式触发的一次活动，新增周期仍保持关闭。
单次执行入口负责统一检查开关、暂停、免打扰、聊天冷却、额度和排他租约。
使用空工具集合构造原生 Runner，由代码核验输出并保存笔记；不把原生全量工具暴露给活动。
资料更新或目标版本改变后，旧结果不能覆盖新进度。

## 3. 统计、恢复与发送约定

- 计数范围为本轮原生 Provider 的实际调用，包括原生 Runner 内部的再次尝试。
  供应商内部 HTTP 重试不等于该计数，usage 为空时明确记录未知，不推算账单。
- 时间、模型和主动分享在工作开始前预留并持久化；上海日界、跨午夜分摊和重启保留消耗在阶段 3 回归。
- 进程排他租约覆盖一次活动至实际结束，读取状态不获取执行租约。
  未确认在途调用结束时保持占用并进入待核实状态，不能把取消请求当作设备或执行器已经释放。
- 开始活动或显式恢复时先验证没有活跃执行者，再处理旧运行记录；只恢复只读资料步骤。
  手动暂停不自动恢复，未知发送不自动重试。
- 自主分享与已有主动聊天共享指定主人私聊的发送额度；普通回复和明确请求的交付另行统计。
  新功能关闭时不改变原有主动聊天流程。
