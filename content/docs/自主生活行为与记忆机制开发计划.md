# 自主生活行为与记忆机制开发计划

制定日期：2026-10-29。开发分支：`feat/life-continuity`。

状态：[阶段 0 兼容清单](自主生活阶段0兼容清单.md)已补齐；阶段 1～3 已本地实现，
交付范围与验证见[阶段 1 说明](自主生活阶段1交付说明.md)、
[阶段 2 说明](自主生活阶段2交付说明.md)和[阶段 3 说明](自主生活阶段3交付说明.md)。
阶段 3 的真实模型与 QQ 单轮实机验收仍待完成，阶段 4、5 待实施。
当前未部署或启用自主活动。以可靠性和稳定性优先，
按阶段交付并验收。参考外部上游的《自主生活开发方案》及相关实现，具体设计以当前私有项目为准。

## 1. 功能简介

让大肥鱼在空闲时选择一个有限的小目标，执行有边界的活动，保存真实经历和进度，
隔天或重启后继续推进，并在日常聊天中说明做过什么、为什么继续、还有什么没弄懂。
她也可以等待、搁置或结束目标，无须每轮都有作品或主动消息。

例如：第一天查阅某款游戏的建造资料，留下一个疑问；第二天找到补充资料并修正理解；
主人询问时能引用实际进展，主人提出新方向后可据此调整；了解足够后结束研究。 这是预期使用场景，不代表机器人已经实际浏览或玩过该游戏。

首轮以“研究一个有限问题并形成可续写的简短笔记”为活动，使用主人明确提供的资料，
或已授权浏览工具的真实读取结果。虚拟房间、游戏操作、可执行技能生成和自我改代码属于后续范围；
本轮不新增公开账号写入、付费或软件安装能力。

## 2. 当前基础与实现原则

编写时，私有项目已有 AstrBot、LivingMemory、主动聊天、网页浏览和手机工具的部署基础，
尚未纳入参考方案中的自主活动插件。外部上游的云端上线记录不能作为当前 Windows 部署的验收结果。

- 复用 AstrBot 原生 Agent、现有人格、QQ 链路和 LivingMemory，不增加独立常驻 Agent 或向量数据库。
- 优先复用参考实现的目标、经历、预算和防重逻辑；先核对依赖及 Windows 兼容性，再决定移植范围。 首轮不以接入整套
  B 站服务、研究方法库或复杂作品管理为前置条件。
- 功能代码放在 `plugins/`，必要的第三方兼容补丁放在 `overlays/`，安装和管理适配放在 `tools/`。 路径通过
  `tools/workspace.py` 解析，不依赖外部参考目录或旧运行目录中的源码副本。
- 配置、SQLite、媒体、备份和凭证保存在独立运行目录。新功能默认关闭，升级保留现有配置及暂停状态。
- 一套调度入口推进本功能，禁止重复启动调度循环；主动分享与现有主动聊天共用发送节流。
  代码负责权限、预算和状态约束，模型只在允许的范围内选择活动。

## 3. 核心机制

### 3.1 目标、经历与记忆

| 数据           | 保存内容                                             | 用途                           |
|----------------|------------------------------------------------------|--------------------------------|
| 目标           | 来源、理由、结束条件、状态、下一步、检查点、版本     | 支持选择、继续、调整与结束     |
| 经历           | 时间、实际读取或操作范围、来源、事实、感想、修订关系 | 解释发生过什么，并支持纠错     |
| 运行与投递记录 | 运行 ID、预算、执行结果、消息标识和回执              | 故障恢复、成本约束与重复抑制   |
| 兴趣证据       | 归属、主题、倾向、独立来源与时间                     | 供后续选择参考，允许衰减和修正 |

SQLite 是目标与执行事实的依据；LivingMemory 负责聊天中的语义召回。
摘要须引用目标或经历标识，模型总结、请求范围和导出路径均不能作为执行成功或 QQ 实收证明。

经历追加保存，纠错通过修订关系保留原始来源；检索优先返回当前有效记录。
自己的兴趣与主人明确表达的偏好分别保存，主人偏好需要真实消息来源。 同一资料重复总结只算一份兴趣证据，一次操作授权不推导为长期偏好。

### 3.2 聊天与经历连通

聊天只读取当前会话相关的少量目标、最近进展、未解决问题及已分享版本，需要详情时再查询经历。
支持回答“最近在忙什么”“为什么继续”“上次做到哪里”“为什么停下来”，回答应可回查来源。

主人普通建议保存为反馈，供下轮选择参考；明确的暂停、继续、调整和取消指令通过受约束的工具更新目标。
更新使用版本检查，避免后台旧状态覆盖刚收到的调整。后台不以旧快照覆盖正常聊天历史。
首轮只向配置的主人私聊开放自主活动，群聊和其他私聊不能读取或修改其记录。

记忆写入失败不丢弃本地经历；结果未知时标为待核对，不盲目重发。 先核验 LivingMemory
实际支持的来源标记、查询和修订方式；缺少核验能力时保留未确认状态。
旧召回与当前修订冲突时以当前事实为准，不能将“进入记忆队列”标为“已保存并召回”。

### 3.3 执行、暂停与跨日恢复

单轮流程：条件检查 → 选择目标 → 持久化运行状态并预留预算 → 执行一个有限步骤 → 保存证据与检查点 →
按需分享 → 结算预算并结束本轮。

| 情况                   | 处理方式                                                         |
|------------------------|------------------------------------------------------------------|
| 主人手动暂停           | 保存原因并禁止自动恢复，等待明确继续                             |
| 前台需要同一设备       | 停止发出新命令，在可中断边界保存进度并释放设备                   |
| 重启或异常中断         | 未完成运行转为中断，目标暂停；重新观察现场后决定是否恢复只读步骤 |
| 设备离线或预算耗尽     | 保留已有进度，待条件恢复后重新评估，不算兴趣下降                 |
| 消息或外部写入结果未知 | 保留原投递或操作标识，先核验，禁止更换标识自动重做               |

手动暂停、系统中断和无进展搁置分别记录原因与恢复策略。未确认设备释放前，不启动第二个操作者。
单轮、模型和工具调用均设置超时；停止后在途调用须在配置超时内结束或进入待核实状态。
后台异常不能阻断普通聊天；本地记录无法可靠保存时，本功能停止执行和分享。

预算按上海日期持久化，明确跨午夜的活动时间分摊和调用归属；重启不能清零或退还未知消耗。
全部新增后台调用入口纳入统计，LivingMemory 等依赖内部不能覆盖的调用另行标注，
不将调用次数宣称为供应商完整账单。额度不足时安静结束。

### 3.4 选择、搁置与结束

先用确定性规则筛选候选，再由模型在候选内选择，并保存本轮理由。初始规则：

- 同时运行一个目标，未结束目标最多三个；优先考虑有明确下一步、近期有进展的目标。
- 候选不足且预算允许时才创建新探索；候选为空可以等待，不强行生成任务。
- 连续三轮实际尝试没有新证据或问题推进时，评估搁置；只改写摘要不算新进展。
- 断线、预算耗尽、前台抢占和等待答复不计为无进展尝试。
- 搁置保存原因、复查时间或重新开启条件，避免下轮立即选回；放弃保存已有发现和原因。
- 主人指定的目标遇到困难时报告并保留，不因兴趣下降而自动取消；已取消目标需明确重开。
- 完成需要满足结束条件并有相关证据，不能仅凭模型自报完成。兴趣选择不增加工具权限。

## 4. 分阶段开发计划

以下列出整体交付顺序，阶段状态以专项交付说明为准；首次单轮实机联调在阶段 3 完成。

| 阶段                | 开发交付                                                                         | 验收条件                                                                                          |
|---------------------|----------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|
| 0：基线与适配清单   | 核对 Agent、记忆、浏览、设备锁、依赖及配置；确定首个真实资料来源和复用范围       | 形成兼容清单；确定单一调度入口、数据路径、统计范围和可用来源，参考测试与本项目基线分开记录        |
| 1：持久化与部署基础 | 接入目标、经历、运行记录、简短笔记检查点；完成迁移、备份、只读状态查询和关闭开关 | 临时运行目录安装及重开数据库成功；重复迁移幂等；旧配置保留；状态查询不触发迁移或恢复              |
| 2：聊天连通与反馈   | 接入相关上下文、经历查询、反馈及明确目标调整；适配记忆保存与召回                 | 进展回答有来源；纠错和版本冲突正确处理；手动暂停有效；会话隔离成立；记忆不可用时可查本地记录      |
| 3：有界执行与恢复   | 接入单次活动、预算、超时、停止、前台优先、恢复、投递账本和跨插件发送节流         | 一次真实研究闭环通过；断线、重启和回执丢失不重复操作；午夜结算与重启额度保持正确                  |
| 4：目标选择与搁置   | 接入候选筛选、兴趣证据、无进展判断、搁置和结束机制                               | 不反复创建同一目标；可解释选择与结束；搁置目标不立即选回；依赖故障不误算放弃理由                  |
| 5：限频试运行       | 完成真实端到端及跨日观察，整理问题和发布验收记录                                 | 观察覆盖 7～14 天；经历、聊天、恢复和发送证据齐全；未验项目保留未验状态，重要修复后重验受影响场景 |

每阶段分别交付实现、相关回归和验证记录，区分代码完成、部署完成与实机验收。 阶段 3 先手动触发一次活动；阶段
4 验证通过后才开放低频周期。

试运行建议上限：每天一次活动、后台累计十分钟、单轮五分钟、单轮十次模型调用、每日二十次。
给主人主动消息建议每天一次，需把自主分享和主动聊天合并统计；自动触发的提议消息也占额度。
普通聊天回复及用户明确请求的结果交付另行统计。现有免打扰和更严格的限制优先， 正式配置在阶段 0
核对后记录，不自动覆盖现有生效设置。

## 5. 验证与首轮完成标准

自动回归使用临时数据库、可控时钟和外部接口替身，覆盖迁移、事务中断、重复触发、
并发更新、重启、午夜切换、超时停止、预算耗尽、会话隔离、来源修订、重复兴趣证据及未知投递结果。 Windows
不支持的参考实现须适配并实际验证，不能只跳过首轮必需能力。

实施阶段按修改范围执行以下检查，保持源码、安装运行回归和真实现场结果分别记录：

```powershell
py -3.12 -m unittest discover -s tests -v
py -3.12 tools/check_release.py
py -3.12 -m compileall -q tools plugins overlays
python tools/launch.py verify
```

最后一项需要已完成安装；Ruff 可用时按项目配置运行。涉及付费模型、QQ 和设备的自动回归使用替身，
现场单次验收再使用真实链路。开发方案文档本身不代表执行过这些检查。

首轮完成须具备以下真实证据：

1. 同一目标从真实来源取得进展，经历中可查来源及实际范围。
2. 打断、重启和实际跨日后继续同一目标，无需主人重新交代背景。
3. 聊天可说明进展、理由及未知部分，主人调整后后续行为随之改变。
4. 至少一次 LivingMemory 保存后实际召回；失败或未知状态可追踪。
5. 完成或搁置有原因与证据，手动暂停不会自动恢复。
6. 预算、免打扰、统一节流和停止生效，无重复投递或越权执行。

验收保存代码版本、配置摘要、时间、目标与运行 ID、来源、检查点、发送回执及记忆结果， 不记录凭证。QQ
接口回执、消息读回和主人实际收到分别记录；时间推进单测不替代真实跨日观察。

## 6. 发布与回退

升级前一致性备份受影响的 SQLite 和配置，采用加法迁移并保留旧数据。
先在临时运行目录验证安装，再部署关闭状态的功能，确认加载后进行单次验收和限频试运行。
功能关闭后，原聊天、人格、记忆和其他暂停任务保持原有状态。

发生故障时先关闭新增调度并停止在途活动，再备份最新状态并回退代码。
已发生的外部操作、消息投递和预算账本不得随旧数据库回滚；旧代码无法理解的数据版本应拒绝运行。
后续活动种类与虚拟环境在本轮验收后另行规划。
