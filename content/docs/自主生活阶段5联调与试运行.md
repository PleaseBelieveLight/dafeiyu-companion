# 自主生活阶段 5：实机联调与限频观察

开始日期：2026-10-30。分支：`feat/life-continuity`。联调版本：`v0.5.0`。

阶段 4 已提交，阶段 5 正在实机联调。插件已部署到实际运行目录，开启严格单次验收模式，
自动分享与周期调度关闭。当前尚未满足正式观察的进入条件，不能标为完成七至十四天试运行。
实际运行标识、原始响应、消息回执和收件确认仅保存在私有运行目录，不纳入 Git。

## 1. 严格限频与管理边界

新增 `trial_mode`，公开默认关闭。开启时采用以下硬上限，已有更严格的限制继续生效：

- 按上海日期，每天最多开始一轮。失败、中断、时间退款和重启均不退还当天名额。
- 每日后台时间不超过十分钟，单轮上限五分钟，单次模型上限六十秒。
  当前单步监督时限仍取单轮与模型时限的较小值，默认六十秒。
- 每轮不超过十次原生 Provider 调用，每日不超过二十次；正常聊天和记忆依赖内部调用另行说明，
  这些计数不是供应商完整账单。
- 自主分享与原主动聊天合并，每日最多一份。前台聊天后至少冷却五分钟，继承现有免打扰。
- 本轮关闭自动分享，通过独立的固定文本验证一次投递。无周期任务，也不补跑遗漏日期。

同一验收计划每天使用稳定触发键，重复请求不会重复执行；真正跨到下一个上海日期后才使用下一日键。
目标不满足恢复条件时仍等待，不因试运行要求而强行解除暂停、生成目标或改写资料。

管理接口仅接收本机已登录 AstrBot 管理端的请求，另检查绑定的管理身份和客户端地址。
不允许客户端选择其他 QQ 会话、执行代码、任意读取文件或提供任意投递正文。
未登录的现场请求返回 401；运行和记忆操作继续受插件、权限包装及作用域检查约束。

## 2. 部署与私有证据

`tools/life_trial.py` 通过 `tools/workspace.py` 查找运行目录。
部署仅涉及本插件及主动发送的两处适配文件，先备份代码、插件配置和已有 SQLite 的一致性快照。
拒绝启用状态下的安装及被重定向的目标路径。实际首次安装保持关闭，再重启受管理的 AstrBot 加载插件，
QQ 进程继续运行；服务就绪后才开启严格单次验收配置。

本地管理凭据只在进程内用于登录，不输出或写入报告。验收快照也不包含 QQ 标识、资料全文或模型原文。

| 私有位置，相对于运行根目录 | 内容 |
| --- | --- |
| `backups/life-trial-*` | 首次安装前的代码、配置及适用的数据库快照 |
| `backups/life-format-fix-*`、`backups/life-memory-lifecycle-*` | 现场修复前的代码副本 |
| `astrbot/data/plugin_data/astrbot_plugin_life_continuity/life.sqlite3` | 实际预算、运行、资料、笔记与投递依据 |
| `astrbot/data/plugin_data/astrbot_plugin_life_continuity/acceptance_diagnostics/` | 按需保存的原始模型响应及摘要校验值 |
| `run/life_trials/<trial_id>/` | 带时间、源码清单、安装匹配情况及人工确认的观察快照 |

诊断接口默认只返回输出字段的类型与长度。管理员明确请求时，可保存该轮原响应到上述私有目录，
不通过接口返回原文。报告保留代码变化提示，始终要求人工验收，不因日期推进自动宣布通过。

## 4. 现场发现与修复

### 模型输出的数组格式

原因：模型将 `questions` 输出为三个字符串组成的数组，原生适配只接受字符串，导致本轮以 `ValueError` 中断。
修复：允许一至八个非空、每项最多一千字的问题列表，确定性合并为文字；其他字段仍严格校验，
不强转对象、空列表或无限长内容。

已返回的原响应经过校验摘要、运行归属、目标版本及当前来源检查后，保存为独立的操作者复核笔记。
原运行仍为中断，模型预算和当天名额不变，不追认自动尝试或兴趣证据。
下一轮仍须真实验证修复后的正常路径；本次复核不替代它。

### 记忆调用与关闭时序

联调发现记忆工具就绪检查和冷启动耗时需要单独记录，不能把依赖插件已激活当作工具可调用。
保存超时后保留未知状态，只允许只读核验；不会通过换经历 ID 绕过重复抑制。
核验用的只读召回可单独设置至多三十秒，管理客户端的等待时限与这些操作对齐。

同时补齐关闭时序：跟踪显式记忆调用的任务，卸载时先请求取消并有界等待；尚未实际退出时保留数据库连接，
退出后再关闭，避免旧回调在关闭的 SQLite 连接上丢失未知状态结算。

启动期间曾有一项既有音乐短超时测试失败；服务完全就绪后，完整已安装回归通过。
本阶段没有为此修改音乐行为或放宽测试。

## 5. 后续操作与验收条件

以下均为人工显式操作，不会安装后台循环。`<trial_id>` 来自私有记录目录：

```powershell
python tools/life_trial.py preflight
python tools/life_trial.py report --trial-id <trial_id>
python tools/life_trial.py snapshot --trial-id <trial_id>
python tools/life_trial.py recall
```

先处理当前记忆未知结果；只有可靠核验明确未写入后，才能讨论新的明确写入。
不要删除或重置账本，也不要换标识重复同一操作。
下一真实日期、免打扰以外，可显式触发一次修复后研究路径：

```powershell
python tools/life_trial.py run --trial-id <trial_id>
```

模型选择、执行和停止继续沿用阶段 3、4 的限制。研究素材不足时补充真实来源或等待，不能把摘要改写当作新进展。
后续覆盖真实前台打断、重启、跨日继续、主人调整、依据纠正和完成/搁置理由，再记录七至十四天的实际观察。
重要代码变化后重验受影响场景，保留变化前后的证据，不拼接成一次无故障验收。

源码回归、离线 SDK、现场联调和合格观察分别记载；当前报告明确为 `incomplete_manual_review_required`。
