# 自主生活阶段 2：聊天连通与反馈

日期：2026-10-29。分支：`feat/life-continuity`。插件版本：`v0.2.0`。

本阶段将本地目标、经历和有效笔记接入主人私聊，提供经历查询、反馈、目标调整和可选的 LivingMemory
桥接。当前完成本地实现与临时集成验证，未部署至实际服务，未启用自主调度。
整体范围见[开发计划](自主生活行为与记忆机制开发计划.md)
，前置存储见[阶段 1 记录](自主生活阶段1交付说明.md)。

后续有界执行与数据库 v3 的实现、当前命令及验证范围见[阶段 3 记录](自主生活阶段3交付说明.md)。 下文保留本阶段
v0.2.0 的交付记录。

## 1. 当前能力

- 聊天请求中提供少量相关目标、理由、下一步、检查点和最近经历；本地上下文最多约六千字。
  不改写聊天历史，不覆盖其他插件的上下文，重复处理同一请求时只保留一份本插件记录。
- 原生只读工具 `life_recall` 按关键词或目标查询当前有效经历，同时返回相关目标及来源标识。
  输出有长度限制；大记录保留标识和截取提示，查不到不意味着历史上未发生。
- 主人建议保存为带真实消息 ID 的反馈，不直接改成兴趣或事实；明确的暂停、继续、取消和
  下一步调整由消息入口执行，模型没有任意修改目标的工具。
- 纠正经历会追加修订并保留原始记录；查询排除旧版本，依赖旧来源的笔记标为需重新核对。
  主人纠正属于有来源的主人陈述，不能冒充重新观察设备取得的事实。
- 记忆桥接区分待写入、发送中、确认保存、结果未知和确认未写入；保存回执与实际召回分别记录。
  所有调用由主人显式发起，本阶段没有自动批量导出、重试循环或记忆定时任务。

## 2. 开关与会话边界

插件配置位于运行根目录下的
`astrbot/data/config/astrbot_plugin_life_continuity_config.json`，更改后重载插件。

| 字段             | 默认值   | 含义                                                           |
|------------------|----------|----------------------------------------------------------------|
| `enabled`        | `false`  | 总开关；关闭时不初始化存储、不注入生活上下文                   |
| `owner_scope`    | 空字符串 | 主人完整私聊会话标识，格式为 `平台实例ID:FriendMessage:主人QQ` |
| `memory_enabled` | `false`  | 允许主人显式调用长期记忆桥接，不影响本地经历查询               |

只允许 QQ 平台、完整会话标识、实际发送者和私聊类型均匹配的事件进入接口。
`owner_scope` 留空时，即使存储开启，也不开放聊天和经历工具。群聊、其他私聊及不匹配的发送者
不能访问或修改记录；请求隐藏工具使用独立工具集合，避免影响其他会话。

默认配置不包含真实账号。普通聊天、转发、引用消息和工具输出不会被当作目标调整命令。
目前仅接收整条直接文本中的明确语法，不自动从所有日常闲聊中推断建议、授权或偏好。

## 3. 主人私聊入口

以下 `目标ID`、`经历ID` 均需使用查询返回的真实标识。ID 可确定目标；同名或多个候选时要求明确指定。

| 输入                                   | 效果                                                   |
|----------------------------------------|--------------------------------------------------------|
| `/life` 或 `/life list`                | 查看目标、状态、完整 ID 和下一步                       |
| `/life pause 目标ID`                   | 手动暂停，等待主人明确继续                             |
| `/life resume 目标ID`                  | 将可恢复的暂停目标设为可继续，保留进度                 |
| `/life cancel 目标ID`                  | 取消目标，保留已有经历                                 |
| `/life adjust 目标ID \| 新的下一步`    | 更新下一步，保留原暂停状态                             |
| `/life feedback 目标ID \| 建议内容`    | 保存主人反馈及消息来源                                 |
| `/life correct 经历ID \| 纠正后的说法` | 追加同一目标、同一会话下的修订                         |
| `/life remember 经历ID`                | 在桥接开启且会话隔离可核验时，保存指定有效经历         |
| `/life recall 关键词`                  | 查询可回查来源的长期记忆；桥接关闭或不可用时查本地经历 |

表格中的分隔符是空格、竖线、空格。例如：

```text
/life feedback 目标ID | 建议先看看联机部分
```

另支持完整短句：`暂停这个目标`、`继续这个目标`、`取消这个目标`，仅在唯一未结束目标时生效； 也支持
`暂停目标 目标ID`、`调整目标 目标ID：新的下一步` 和 `关于目标 目标ID：建议内容`。
模糊的“可以”“算了”、疑问和转述不触发修改。

重复消息不重复保存反馈或修改目标；同一消息 ID 对应不同内容时拒绝处理。
修改使用目标版本检查，并与审计记录放在同一事务。过期版本拒绝覆盖新状态。
进行中、等待审批、待核实或已结束的目标不能通过这些命令强行恢复或改写。 本阶段不停止在途设备操作；运行中记录需按阶段
3 的停止与恢复机制处理。

本阶段不通过聊天创建新目标或执行目标。已有目标来自受信任的存储接口，后续由有界活动流程创建。

## 4. LivingMemory 适配

复用实际注册的 `memorize_long_term_memory` 和 `recall_long_term_memory`，调用保留原工具权限包装，
并使用真实主人事件构造 AstrBot 上下文。调用前使用依赖自身的作用域解析函数确认结果等于当前私聊，
不能核验或配置为跨会话共享时，只保留本地经历及待处理状态，不修改依赖的全局配置。

每次导出引用目标和经历 ID，正文附来源标记。依赖没有来源幂等保证，因此本地账本先记录发送中：

- 缺少工具或隔离条件不足：保留待写入，不调用依赖。
- 写入确认包含有效记忆 ID 和正确作用域：标为已保存，召回仍未验证。
- 明确的初始化或访问拒绝：标为确认未写入，主人再次显式请求时才可重试。
- 超时、内部错误、回执不完整、取消或重启留下的发送中状态：保留未知，不自动重复写入。

同一经历在同一插件实例并发导出时合并在途状态。召回通过返回的记忆 ID 或来源标记回查当前有效
本地经历，不把过期、其他会话或无法追溯的语义结果返回为事实。未知写入可通过召回核验， 无法找到来源标记或有效
ID 时继续保持未确认，不能声称恰好保存一次。

等待外部调用期间发生的纠正会重新核对：旧来源不标为当前事实，本地回退也重新查询。 本阶段不自动删除或重写
LivingMemory 中的旧条目；聊天明确以当前本地修订为准。

## 5. 数据升级与查询

数据库由 v1 加法迁移至 v2，新增 `chat_events` 与 `memory_exports`，原目标、经历、笔记和运行保留。 升级前使用
SQLite 在线备份保存 v1，包括已提交 WAL；失败时结构和版本一起回滚。 重复初始化不重复迁移，打开数据库不恢复运行，旧代码不能写入更高版本的库。

`python tools/life_state.py` 仍为只读查询；旧 v1 库只读取原结构，不触发升级。 指定 `--scope`
后可额外查看该会话的记忆投递状态和召回核验标志。 回退前关闭新插件并保存最新库和配置，不用旧库覆盖已发生的记忆写入账本。
